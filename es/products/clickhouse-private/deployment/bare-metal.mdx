<div id="download-and-install-terraform">

</div>

```
dnf install -y unzip git
```

```
curl -O  https://releases.hashicorp.com/terraform/1.13.2/terraform_1.13.2_linux_amd64.zip
```

```
unzip terraform_1.13.2_linux_amd64.zip
```

```
sudo cp terraform /usr/local/bin
```

```
terraform version
```

```
Terraform v1.13.2
on linux_amd64
```

<div id="acquire-aws-iam-credentials-and-create-a-credentials-file">
  #### Obtenga credenciales de AWS IAM y cree un archivo de credenciales
</div>

Visite la consola de AWS IAM, cree una clave de acceso y una clave secreta,
y guarde estos valores.

**NOTA**
Reemplace `<Your AWS ACCESS KEY ID>` y `<Your AWS SECRET ACCESS KEY>` por los
valores obtenidos en la consola de AWS IAM.

```
cat > aws-creds.sh <<EOF
export AWS_ACCESS_KEY_ID=<Your AWS ACCESS KEY ID>
export AWS_SECRET_ACCESS_KEY=<Your AWS SECRET ACCESS KEY>
export AWS_REGION=us-east-2
EOF
```

<div id="load-your-aws-iam-credentials">
  #### Carga tus credenciales de IAM de AWS
</div>

```
source ./aws-creds.sh
```

**NOTA - Agrega `-migrate-state` si estás moviendo el estado de local a S3**

<div id="initialize-the-rke2-terraform-module">
  #### Inicializar el módulo de Terraform de rke2
</div>

```
terraform -chdir=modules/rke2 init \ 
-backend-config="encrypt=true" \
-backend-config="region=us-east-2" \
-backend-config="bucket=chb-tfstate-359774249275" \
-backend-config="use_lockfile=true" \
-backend-config="key=chb/rke2/terraform.tfstate"
```

<div id="issue-a-terraform-apply-command-to-bring-the-stack-up">
  #### Ejecuta `terraform apply` para poner en marcha la pila
</div>

Desde el directorio `terraform` ubicado en el repositorio de Git

```
terraform -chdir=modules/rke2 apply \
-var-file=../../vars/common.tfvars \
-var-file=../../vars/instances.tfvars \
-var-file=../../vars/rke2.tfvars
```

<div id="1-helm-variables-script-1_set-helm-varssh">
  ##### 1. Script de variables de Helm (1_set-helm-vars.sh)
</div>

Este script define todas las variables de entorno necesarias para el despliegue con Helm.

```bash
#!/bin/bash
# Credenciales AWS/S3
export AWS_ACCESS_KEY_ID=<your_aws_key>
export AWS_SECRET_ACCESS_KEY=<your_aws_secret>
export AWS_REGION=<your_aws_region>
export S3_ACCESS_KEY_ID=<s3_or_minio_key>
export S3_SECRET_ACCESS_KEY=<s3_or_minio_secret>
export S3_REGION=us-east-1
export ECR_HOST=<ecr_host>
# Establece las AZs según las subredes de la VPC. Si no aplica, usa los nombres de host de tu clúster k8s.
export AZ_LIST='["<your_host_1>", "<your_host_2>", "<your_host_3>","<your_host_4>", "<your_host_5>", "<your_host_6>"]'

# Lista de variables de entorno requeridas
REQUIRED_VARS=(
    "AWS_ACCESS_KEY_ID"
    "AWS_SECRET_ACCESS_KEY"
    "AWS_REGION"
    "S3_ACCESS_KEY_ID"
    "S3_SECRET_ACCESS_KEY"
    "S3_REGION"
    "ECR_HOST"
    "MINIO_TENANT_NAME"
    "MINIO_ACCESS_KEY"
    "MINIO_SECRET_KEY"
)

# Inicializa un indicador para rastrear si falta alguna variable
MISSING_VARS=0

# Itera sobre el array de variables requeridas
for VAR in "${REQUIRED_VARS[@]}"; do
    # Verifica si la variable está definida y no está vacía
    if [ -z "${!VAR}" ]; then
        echo "🚨 ERROR: Required environment variable ${VAR} is not set."
        MISSING_VARS=1
    fi
done

# Mensaje de estado final
if [ "$MISSING_VARS" -eq 0 ]; then
    echo "✅ Success! All required environment variables are set."
else
    echo "❌ Please set the missing environment variables and try again."
    exit 1 # Sale con un estado distinto de cero para indicar fallo
fi

PASSWORD='My super secret p@$$w0rd'
export HASHED_PASSWORD=$(echo -n "$PASSWORD" | sha256sum | awk '{printf $1}' | base64 -w 0)
export CLUSTER_NAME="baremetal-ch-01"
export CHART_VERSION="1.1.84"

export SERVER_NG_GROUP="server-amd64"
export KEEPER_NG_GROUP="keeper-amd64"
export KEEPER_CPU="4"
export KEEPER_MEMORY="16Gi"

#export SERVER_CPU="7"
export SERVER_MEMORY="128Gi" # se necesitan 406948151296 de disco
export SERVER_CPU="64"
#export CACHE_DISK_SIZE_GI=379Gi
export CACHE_DISK_SIZE_GI=10Gi
#export SERVER_MEMORY="128Gi"
TARGET_SCRIPT_FULL_PATH="$(dirname "${BASH_SOURCE[0]}")/set_helm_vars.sh"
SYMLINK_FULL_PATH="$(dirname "${BASH_SOURCE[0]}")/$(basename "${BASH_SOURCE[0]}")"
if [[ "$(basename "${BASH_SOURCE[0]}")" != "set_helm_vars.sh" ]]; then
```

<div id="run-3_helm_install_clickhousesh">
  ###### Ejecute 3_helm_install_clickhouse.sh
</div>

Este script automatiza el proceso de instalación o actualización con Helm del clúster principal de ClickHouse, cargando las variables y preparando el archivo de valores.

```bash
  #!/bin/bash
  source ./set_helm_vars.sh
  
  # Preparar un archivo de valores temporal expandiendo las variables en my-dynamic-values.yaml.
  echo "Expanding YAML values from my-dynamic-values.yaml using envsubst..."
  TEMP_VALUES_FILE=$(mktemp) # Crear un archivo temporal único
  if ! envsubst < clickhouse-values.yaml > "$TEMP_VALUES_FILE"; then
      echo "Error: Failed to expand variables in my-dynamic-values.yaml using envsubst."
      rm -f "$TEMP_VALUES_FILE" # Eliminar el archivo temporal en caso de error
      exit 1
  fi
  
  # Crear el espacio de nombres para el clúster
  kubectl create namespace ns-$CLUSTER_NAME
  
  # Asegurarse de que el secreto del registro de Docker esté actualizado.
  kubectl create secret docker-registry all-icr-io --docker-server=359774249275.dkr.ecr.us-east-2.amazonaws.com --docker-username=AWS --docker-password=$(aws ecr get-login-password) -n ns-$CLUSTER_NAM
  
  echo "Performing helm install for release '$CLUSTER_NAME'..."
  if ! helm upgrade "$CLUSTER_NAME" \
    oci://$ECR_HOST/helm/onprem-clickhouse-cluster \
    --install --reuse-values \
    --version="$CHART_VERSION" \
    -n ns-$CLUSTER_NAME \
    --create-namespace \
    --values "$TEMP_VALUES_FILE" \
    --timeout 10m0s; then
      echo "Error: Helm upgrade failed. Please review the output above for details."
      rm -f "$TEMP_VALUES_FILE" # Eliminar el archivo temporal en caso de error
      exit 1
  fi
  
  echo "Helm install completed successfully!"
  
  # 5. Eliminar el archivo de valores temporal.
  echo "Cleaning up temporary values file..."
  rm "$TEMP_VALUES_FILE"
  
  # 6. Supervisar los pods para ver el efecto de la actualización.
  echo "Monitoring pod status in namespace 'clickhouse-operator-system' (Ctrl+C to exit monitoring):"
  kubectl get pods -n clickhouse-operator-system -w
  
  echo "--- Helm Upgrade Process Complete ---"
```

<div id="4-fix-keeper-statefulset-4_fix_keeper_stssh">
  ##### 4. Corregir el StatefulSet de Keeper (4_fix_keeper_sts.sh)

Este script se utiliza para aplicar un parche al secreto de Kubernetes y al StatefulSet de ClickHouse Keeper, lo que puede ser crucial para resolver ciertos problemas de acceso relacionados con los secretos necesarios para descargar imágenes o con las variables de entorno. Garantiza que los pods de Keeper puedan acceder correctamente a los recursos necesarios.


<div id="sts_keeper_patch_templateyaml">
  ###### sts_keeper_patch_template.yaml
</div>

Esta plantilla YAML se utiliza en el script 5&#95;fix&#95;keeper&#95;sts.sh para aplicar un parche al StatefulSet de ClickHouse Keeper. Agrega imagePullSecrets e inyecta la clave de acceso y la clave secreta de AWS como variables de entorno en el contenedor de Keeper.

```yaml
  apiVersion: apps/v1
  kind: StatefulSet
  metadata:
    name: c-$CLUSTER_NAME-keeper
    namespace: ns-$CLUSTER_NAME
  spec:
    template:
      spec:
        imagePullSecrets:
          - name: all-icr-io
        containers:
          - name: c-$CLUSTER_NAME-keeper
            env:
            - name: AWS_ACCESS_KEY_ID
              value: $S3_ACCESS_KEY_ID
            - name: AWS_SECRET_ACCESS_KEY
              value: $S3_SECRET_ACCESS_KEY
```

<div id="sts_server_patchsh">
  ###### sts_server_patch.sh
</div>

Este script está diseñado para aplicar parches a los StatefulSets de los pods de Kubernetes de ClickHouse server. Garantiza que el secreto necesario para la extracción de imágenes se aplique a los StatefulSets del servidor, lo cual es fundamental para descargar imágenes de contenedor desde registros privados como IBM Cloud Container Registry. También incluye manejo de errores e informa al usuario de que es necesario reiniciar un pod para que los cambios surtan efecto.

```bash
#!/bin/bash
# Salir inmediatamente si un comando termina con un estado distinto de cero.
set -euo pipefail

# --- Configuración y validación ---
# El espacio de nombres y el nombre del secreto se pasan ahora como argumentos.

if [ "$#" -ne 2 ]; then
  echo "Usage: $0 <NAMESPACE> <IMAGE_PULL_SECRET_NAME>"
  echo "Example: $0 ns-my-cluster all-icr-io"
  exit 1
fi

TARGET_NAMESPACE="$1"
SECRET_NAME="$2"

# --- Lógica del script ---

echo "--> Verifying secret '$SECRET_NAME' in namespace '$TARGET_NAMESPACE'..."
# 'set -e' hará que el script termine si no se encuentra el secreto.
kubectl get secret "$SECRET_NAME" -n "$TARGET_NAMESPACE" >/dev/null
echo "    Secret found. Proceeding."

echo "--> Finding StatefulSets containing 'server' in their name..."
# Usar una consulta jsonpath más fiable para obtener los nombres directamente.
# El '|| true' garantiza que el script no falle si no se encuentran StatefulSets.
STS_LIST=$(kubectl get sts -n "$TARGET_NAMESPACE" --no-headers -o custom-columns=NAME:.metadata.name | grep "server" || true)

if [ -z "$STS_LIST" ]; then
  echo "    No matching 'server' StatefulSets found. Nothing to patch."
  exit 0
fi

echo "--> Found the following StatefulSets to patch:"
echo "$STS_LIST"

PATCH_JSON='{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"'"$SECRET_NAME"'"}]}}}}'

for STS_NAME in $STS_LIST; do
  echo "    - Patching ${STS_NAME}..."
  # Aplicar el parche al StatefulSet. Redirigir la salida exitosa a /dev/null para registros más limpios.
  kubectl patch sts "$STS_NAME" -n "$TARGET_NAMESPACE" -p "$PATCH_JSON" >/dev/null
done

echo
echo "--> Patching process complete."
echo "--> IMPORTANT: Pods must be restarted for the new imagePullSecrets to take effect."
echo "    Example: kubectl delete pod <pod-name> -n ${TARGET_NAMESPACE}"
```

<div id="s3-access-denied-errors">
  ##### Errores de &quot;Access Denied&quot; de S3
</div>

Si encuentras errores de Access Denied relacionados con S3 en los logs del contenedor (p. ej., en instancias de Keeper), es posible que necesites inyectar las credenciales de S3 en las variables de entorno del pod de Kubernetes. En lugar de `kubectl edit`, puedes usar `kubectl patch` con un archivo YAML.

Error de ejemplo:

```bash
2025.07.10 20:12:36.893641 [ 1 ] {} <Error> Application: Code: 499. DB::Exception: Message: Access Denied, bucket ch-s3-bb1bf91e-0eae-4d02-a842-e75d660d62bc, key ch-s3-00000000-0000-0000-0000-000000000000/keepers/0/log/clickhouse_access_check_eacdcaed-ef86-488c-ae77-22a7ec0db795, object size 4: While checking access for disk s3_keeper_log_disk. (S3_ERROR), Stack trace (when copying this message, always include the lines below): 
```

Cree un archivo llamado sts&#95;keeper&#95;patch.yaml con el siguiente contenido y sustituya YOUR&#95;KEY y YOUR&#95;SECRET por sus credenciales reales de AWS:

```yaml
apiVersion: apps/v1 
kind: StatefulSet 
metadata: 
  name: c-default-xx-01-keeper 
  namespace: ns-default-xx-01 
spec: 
  template: 
    spec: 
      containers: 
        - name: c-default-xx-01-keeper 
          env: 
          - name: AWS_ACCESS_KEY_ID 
            value: YOUR_KEY # Reemplaza con tu AWS Access Key ID 
          - name: AWS_SECRET_ACCESS_KEY 
            value: YOUR_SECRET # Reemplaza con tu AWS Secret Access Key 
```

A continuación, aplica el parche:

```bash
kubectl patch sts c-default-xx-01-keeper -n ns-default-xx-01 --patch-file sts_keeper_patch.yaml 
```

Después de aplicar el parche, supervise los pods. Es posible que tenga que eliminar el pod de Kubernetes problemático para forzar que se vuelva a crear con la nueva configuración:

```bash
kubectl delete pod c-default-xx-01-keeper-0 -n ns-default-xx-01 
```

Copiar el secreto de kubectl a otro espacio de nombres (si es necesario)

Si necesitas copiar tu secreto de kubectl a otro espacio de nombres (p. ej., de default a clickhouse-operator-system), usa el siguiente comando. Los scripts deberían encargarse de esto automáticamente.

```bash
kubectl get secret all-icr-io -n default -o yaml | \

  sed 's/  resourceVersion: .*//g' | \ 
  sed 's/  uid: .*//g' | \
```

<div id="run-script-remove_cached_imagessh">
  ##### Ejecutar el script remove_cached_images.sh
</div>

```bash
#!/bin/bash 
set -e 
 
echo "Starting cleanup process on all nodes..." 
echo "-----------------------------------" 
 
kubectl get nodes -o name | while read -r node_ref; do 
  node_name="${node_ref}" 
 
  echo "--> Processing $node_name" 
 
  # Paso 1: Ejecutar el comando de depuración y capturar TODA la salida en una variable. 
  # El '2>&1' garantiza que tanto la salida estándar como los errores se capturen. 
  CMD_OUTPUT=$(kubectl debug $node_ref  \ 
    -n default -it --image=busybox --profile=general \ 
    -- sh -c 'chroot /host crictl rmi --all' 2>&1) 
 
  # Paso 2: Imprimir solo las líneas que comiencen con "Creating" o "Deleted". 
  # El indicador '-E' habilita expresiones regulares extendidas para el operador '|' (OR). 
  # El '^' ancla la coincidencia al inicio de la línea. 
  echo "$CMD_OUTPUT" | grep -E '^Creating|^Deleted' 
 
  # Paso 3: Analizar la salida completa para encontrar el nombre del pod que se eliminará. 
  captured_pod_name=$(echo "$CMD_OUTPUT" | grep "Creating debugging pod" | awk '{print $4}') 
   
  if [ -n "$captured_pod_name" ]; then 
    echo "Cleaning up pod: $captured_pod_name" 
    kubectl delete pod "$captured_pod_name" -n default --wait=false 
  else 
    echo "    Warning: Could not determine pod name for node $node_name." 
  fi 
 
  echo "-----------------------------------" 
done 
 
echo "All nodes have been processed." 
```
