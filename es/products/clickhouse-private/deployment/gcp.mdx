<div id="overview">
  ## Descripción general
</div>

Esta guía explica cómo implementar ClickHouse Private en Google Cloud Platform (GCP) con Google Kubernetes Engine (GKE). Adapta el proceso de implementación estándar de AWS a los servicios específicos de GCP, incluidos Artifact Registry, GCS con API compatible con S3 y Workload Identity.

Esta guía admite implementaciones **estándar** y **compatibles con FIPS 140-2**. Los pasos y la configuración específicos de FIPS se indican con **(FIPS)** en todo el documento. Configure `ENABLE_FIPS=true` en `00-env.sh` para habilitar el modo FIPS.

<div id="prerequisites">
  ## Requisitos previos
</div>

* Proyecto de GCP con la facturación activada
* CLI de `gcloud` instalada y autenticada
* `kubectl` instalado
* `helm` v3.x instalado
* `skopeo` instalado (para copiar imágenes de contenedor)
* Credenciales de AWS con acceso de lectura a ECR de ClickHouse (para copiar imágenes)
* **Host bastión** en la VPC para acceder al clúster privado
* **Cuenta de servicio de despliegue** con los permisos adecuados (consulta más abajo)
* **(FIPS)** Acceso a la imagen de contenedor Red Hat UBI8 (obtenida mediante GKE para la generación de certificados)

<div id="creating-a-service-account-for-clickhouse-deployment">
  ## Creación de una cuenta de servicio para la implementación de ClickHouse
</div>

En entornos FedRAMP donde la autenticación directa de usuarios está restringida, cree una cuenta de servicio para la suplantación de identidad.

<div id="option-1-via-gcp-console">
  ### Opción 1: Desde la consola de GCP
</div>

1. Ve a **IAM &amp; Admin** → **Service Accounts**
2. Haz clic en **+ CREATE SERVICE ACCOUNT**
3. Introduce:
   * **Name:** `clickhouse-deployer`
   * **ID:** `clickhouse-deployer`
   * **Description:** `Service account for deploying ClickHouse infrastructure`
4. Haz clic en **CREATE AND CONTINUE**
5. Agrega los siguientes roles:

| Rol                                     | Propósito                                            |
| --------------------------------------- | ---------------------------------------------------- |
| `roles/compute.networkAdmin`            | Crear/administrar VPC, subredes, NAT y enrutadores   |
| `roles/container.admin`                 | Crear/administrar clústeres de GKE y grupos de nodos |
| `roles/storage.admin`                   | Crear/administrar buckets de GCS                     |
| `roles/iam.serviceAccountAdmin`         | Crear/administrar cuentas de servicio                |
| `roles/iam.serviceAccountUser`          | Usar cuentas de servicio para Workload Identity      |
| `roles/iam.workloadIdentityUser`        | Configurar bindings de Workload Identity             |
| `roles/artifactregistry.admin`          | Crear/administrar repositorios de Artifact Registry  |
| `roles/resourcemanager.projectIamAdmin` | Administrar políticas de IAM en el proyecto          |

6. Haz clic en **CONTINUE** → **DONE**

**Concede el permiso Token Creator:**

1. Haz clic en la cuenta de servicio `clickhouse-deployer` recién creada
2. Ve a la pestaña **PERMISSIONS**
3. Haz clic en **GRANT ACCESS**
4. Agrega el principal: `<COMPUTE_SERVICE_ACCOUNT>@developer.gserviceaccount.com` (la cuenta de servicio de tu bastión)
5. Asigna el rol: `roles/iam.serviceAccountTokenCreator`
6. Haz clic en **SAVE**

<div id="option-2-via-cli-requires-iam-admin-access">
  ### Opción 2: Mediante la CLI (requiere acceso de administrador de IAM)
</div>

```bash expandable
PROJECT_ID=your-project-id
SA_EMAIL=clickhouse-deployer@${PROJECT_ID}.iam.gserviceaccount.com
COMPUTE_SA=<COMPUTE_PROJECT_NUMBER>-compute@developer.gserviceaccount.com

# Crear cuenta de servicio
gcloud iam service-accounts create clickhouse-deployer \
  --display-name="ClickHouse Deployer" \
  --project=${PROJECT_ID}

# Asignar roles
for role in \
  roles/compute.networkAdmin \
  roles/container.admin \
  roles/storage.admin \
  roles/iam.serviceAccountAdmin \
  roles/iam.serviceAccountUser \
  roles/iam.workloadIdentityUser \
  roles/artifactregistry.admin \
  roles/resourcemanager.projectIamAdmin
do
  gcloud projects add-iam-policy-binding ${PROJECT_ID} \
    --member="serviceAccount:${SA_EMAIL}" \
    --role="${role}"
done

# Permitir que la SA de compute la suplante
gcloud iam service-accounts add-iam-policy-binding ${SA_EMAIL} \
  --member="serviceAccount:${COMPUTE_SA}" \
  --role="roles/iam.serviceAccountTokenCreator" \
  --project=${PROJECT_ID}
```

<div id="configure-impersonation-on-bastion">
  ### Configurar la suplantación en el bastión
</div>

Añade esto a tu `00-env.sh` o ejecútalo antes de ejecutar los scripts:

```bash
# Configurar la suplantación para la cuenta de servicio del desplegador
gcloud config set auth/impersonate_service_account clickhouse-deployer@${GCP_PROJECT}.iam.gserviceaccount.com

# Verificar que funciona
gcloud compute networks list --project=${GCP_PROJECT}
```

Para salir de la suplantación más tarde:

```bash
gcloud config unset auth/impersonate_service_account
```

<div id="00-environment-variables">
  ## 00. Variables de entorno
</div>

**Archivo: `00-env.sh`**

```bash expandable
#!/bin/bash
# ============================================
# ClickHouse Private GCP - Configuración del entorno
# ============================================
# Actualice estos valores para su entorno

# Proyecto y región de GCP
export GCP_PROJECT=your-project-id
export GCP_REGION=us-central1
export GCP_ZONES="us-central1-a,us-central1-b,us-central1-c"

# Clúster de GKE
export GKE_CLUSTER_NAME=clickhouse-cluster

# Clúster de ClickHouse (puede haber varios por clúster de GKE)
export CLUSTER_NAME=default-xx-01
export NAMESPACE=ns-${CLUSTER_NAME}

# Redes - Use la VPC existente donde reside el bastión
export VPC_NAME=clickhouse-vpc
export SUBNET_NAME=gke-subnet
export SUBNET_RANGE=10.1.0.0/24
export POD_RANGE=10.244.0.0/14         # Debe estar en límite /14 (3er octeto divisible por 4)
export SERVICE_RANGE=10.252.0.0/20     # Debe estar en límite /20
export MASTER_IPV4_CIDR=172.16.0.0/28  # Para el plano de control del clúster privado
export BASTION_SUBNET_RANGE=10.0.0.0/24  # Subred del bastión (para master-authorized-networks)

# Almacenamiento
export BUCKET_NAME=clickhouse-data-${GCP_PROJECT}
export S3_KEY_PREFIX=ch-s3-$(uuidgen | tr '[:upper:]' '[:lower:]')

# Cuentas de servicio
export GSA_NAME=clickhouse
export GSA_EMAIL=${GSA_NAME}@${GCP_PROJECT}.iam.gserviceaccount.com
export KSA_NAME=clickhouse

# Registro de artefactos
export GAR_REPO_NAME=clickhouse
export GAR_HOST=${GCP_REGION}-docker.pkg.dev/${GCP_PROJECT}/${GAR_REPO_NAME}

# Configuración FIPS (establezca en true para cumplimiento con FIPS 140-2)
export ENABLE_FIPS=false

# Versiones de imagen - El modo FIPS utiliza compilaciones conformes con FIPS
if [ "$ENABLE_FIPS" = "true" ]; then
  export CLICKHOUSE_SERVER_VERSION=25.8.1.9104-fips
  export CLICKHOUSE_KEEPER_VERSION=26.1.1.1493
else
  export CLICKHOUSE_SERVER_VERSION=25.8.1.9104
  export CLICKHOUSE_KEEPER_VERSION=25.10.1.6624
fi
export CLICKHOUSE_OPERATOR_VERSION=main-1.16067.1
export OPERATOR_HELM_VERSION=1.16067.1
export CLUSTER_HELM_VERSION=1.1.155

# Origen de AWS ECR (para copiar imágenes)
export SOURCE_ECR_REGION=us-east-1
export SOURCE_ECR_REPO=349290138304.dkr.ecr.${SOURCE_ECR_REGION}.amazonaws.com
export AWS_PROFILE=clickhouse-ecr

# Configuración del grupo de nodos
export KEEPER_MACHINE_TYPE=n2-standard-4      # n2-standard-8 recomendado para producción
export SERVER_MACHINE_TYPE=n2-standard-8      # n2-standard-64 recomendado para producción
export DEFAULT_MACHINE_TYPE=n2-standard-4

# Límites de recursos (ajuste según el tamaño de las instancias)
export SERVER_CPU=4                           # Ajuste al tipo de máquina
export SERVER_MEMORY=16Gi                     # Ajuste al tipo de máquina
export KEEPER_CPU=2
export KEEPER_MEMORY=8Gi

# Configuración de caché
export CACHE_BYTES_PER_GI_RAM=11Gi

# Configuración de certificados FIPS (solo se usa cuando ENABLE_FIPS=true)
if [ "$ENABLE_FIPS" = "true" ]; then
  export KUBERNETES_DOMAIN=cluster.local
  export CERT_DIR=./certs
  export SELF_SIGNED=true  # Establezca en false si usa una CA existente
fi

# Contraseña de ClickHouse
# Para producción/FIPS: use Secret Manager en su lugar:
#   export CLICKHOUSE_PASSWORD=$(gcloud secrets versions access latest --secret=clickhouse-password --project=${GCP_PROJECT})
export CLICKHOUSE_PASSWORD='change-me-not-for-production'

echo "=========================================="
echo "Environment Variables Set"
echo "=========================================="
echo "GCP Project:     ${GCP_PROJECT}"
echo "GCP Region:      ${GCP_REGION}"
echo "GKE Cluster:     ${GKE_CLUSTER_NAME}"
echo "CH Cluster:      ${CLUSTER_NAME}"
echo "Namespace:       ${NAMESPACE}"
echo "VPC:             ${VPC_NAME}"
echo "Subnet:          ${SUBNET_NAME}"
echo "Bucket:          ${BUCKET_NAME}"
echo "GAR Host:        ${GAR_HOST}"
echo "FIPS Mode:       ${ENABLE_FIPS}"
echo "=========================================="
```

**Importante:** Carga este archivo con source antes de ejecutar otros scripts:

```bash

```

<div id="02-copy-container-images">
  ## 02. Copiar imágenes de contenedor
</div>

**Archivo: `02-copy-images.sh`**

Requiere [skopeo](https://github.com/containers/skopeo) para conservar todas las arquitecturas.

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "02. Copying ClickHouse Images"
echo "=========================================="

# Verificar que el perfil de AWS existe
if ! aws configure list --profile ${AWS_PROFILE} &>/dev/null; then
  echo "ERROR: AWS profile '${AWS_PROFILE}' not found"
  echo "To create the profile, run: aws configure --profile ${AWS_PROFILE}"
  exit 1
fi

# Autenticarse en el ECR de origen
echo "Authenticating to AWS ECR..."
aws ecr get-login-password --region ${SOURCE_ECR_REGION} --profile ${AWS_PROFILE} | \
  skopeo login --username AWS --password-stdin ${SOURCE_ECR_REPO}
echo "✓ ECR authentication successful"

# Autenticarse en GCP Artifact Registry
echo "Authenticating to GCP Artifact Registry..."
gcloud auth configure-docker ${GCP_REGION}-docker.pkg.dev --quiet
echo "✓ GAR authentication successful"

echo ""
echo "Copying images..."

echo "1/5 Copying ClickHouse Server ${CLICKHOUSE_SERVER_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/clickhouse-server:${CLICKHOUSE_SERVER_VERSION} \
  docker://${GAR_HOST}/clickhouse-server:${CLICKHOUSE_SERVER_VERSION}
echo "✓ Server copied"

echo "2/5 Copying ClickHouse Keeper ${CLICKHOUSE_KEEPER_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/clickhouse-keeper:${CLICKHOUSE_KEEPER_VERSION} \
  docker://${GAR_HOST}/clickhouse-keeper:${CLICKHOUSE_KEEPER_VERSION}
echo "✓ Keeper copied"

echo "3/5 Copying ClickHouse Operator ${CLICKHOUSE_OPERATOR_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/clickhouse-operator:${CLICKHOUSE_OPERATOR_VERSION} \
  docker://${GAR_HOST}/clickhouse-operator:${CLICKHOUSE_OPERATOR_VERSION}
echo "✓ Operator copied"

echo "4/5 Copying Operator Helm Chart ${OPERATOR_HELM_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/helm/clickhouse-operator-helm:${OPERATOR_HELM_VERSION} \
  docker://${GAR_HOST}/helm/clickhouse-operator-helm:${OPERATOR_HELM_VERSION}
echo "✓ Operator Helm chart copied"

echo "5/5 Copying Cluster Helm Chart ${CLUSTER_HELM_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/helm/onprem-clickhouse-cluster:${CLUSTER_HELM_VERSION} \
  docker://${GAR_HOST}/helm/onprem-clickhouse-cluster:${CLUSTER_HELM_VERSION}
echo "✓ Cluster Helm chart copied"

echo ""
echo "=========================================="
echo "✅ All images copied successfully!"
echo "=========================================="

# Verificar
echo ""
echo "Verifying images in Artifact Registry..."
gcloud artifacts docker images list ${GAR_HOST} --format="table(package,version)"
```

<div id="03-configure-vpc-and-subnet">
  ## 03. Configurar VPC y subred
</div>

**Archivo: `03-vpc-subnet.sh`**

Este script asume que ya tienes una VPC existente con un host bastión. Crea o actualiza la subred de GKE con los rangos secundarios necesarios.

**Importante: Requisitos de límites CIDR**

* bloques `/14`: el tercer octeto debe ser divisible por 4 (p. ej., `10.244.0.0`, NO `10.245.0.0`)
* bloques `/20`: el cuarto octeto debe ser 0 y el tercer octeto debe estar alineado a 16 (p. ej., `10.252.0.0`)

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "03. Configuring VPC and GKE Subnet"
echo "=========================================="

# Verificar si existe la VPC
echo "Checking VPC: ${VPC_NAME}..."
if gcloud compute networks describe ${VPC_NAME} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ VPC exists"
else
  echo "   Creating VPC..."
  gcloud compute networks create ${VPC_NAME} \
    --subnet-mode=custom \
    --project=${GCP_PROJECT}
  echo "   ✓ VPC created"
fi

# Verificar si existe la subred de GKE
echo ""
echo "Checking GKE subnet: ${SUBNET_NAME}..."
if gcloud compute networks subnets describe ${SUBNET_NAME} --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  # La subred existe - verificar rangos secundarios
  EXISTING_SECONDARY=$(gcloud compute networks subnets describe ${SUBNET_NAME} \
    --region=${GCP_REGION} \
    --project=${GCP_PROJECT} \
    --format="value(secondaryIpRanges.rangeName)" 2>/dev/null | grep -E "^pods$" || true)
  
  if [ -z "$EXISTING_SECONDARY" ]; then
    echo "   ⚠️ Subnet exists but missing secondary ranges"
    echo "   Adding secondary ranges for pods and services..."
    gcloud compute networks subnets update ${SUBNET_NAME} \
      --region=${GCP_REGION} \
      --add-secondary-ranges=pods=${POD_RANGE},services=${SERVICE_RANGE} \
      --project=${GCP_PROJECT}
    echo "   ✓ Secondary ranges added"
  else
    echo "   ✓ Subnet exists with secondary ranges"
  fi
else
  echo "   Creating GKE subnet..."
  gcloud compute networks subnets create ${SUBNET_NAME} \
    --network=${VPC_NAME} \
    --region=${GCP_REGION} \
    --range=${SUBNET_RANGE} \
    --secondary-range=pods=${POD_RANGE},services=${SERVICE_RANGE} \
    --enable-private-ip-google-access \
    --project=${GCP_PROJECT}
  echo "   ✓ Subnet created"
fi

# Habilitar Private Google Access
echo ""
echo "Ensuring Private Google Access is enabled..."
gcloud compute networks subnets update ${SUBNET_NAME} \
  --region=${GCP_REGION} \
  --enable-private-ip-google-access \
  --project=${GCP_PROJECT} 2>/dev/null || true
echo "   ✓ Private Google Access enabled"

echo ""
echo "=========================================="
echo "✅ VPC/Subnet Configuration Complete!"
echo "=========================================="
echo ""
echo "VPC:          ${VPC_NAME}"
echo "GKE Subnet:   ${SUBNET_NAME} (${SUBNET_RANGE})"
echo "Pods:         ${POD_RANGE}"
echo "Services:     ${SERVICE_RANGE}"
echo "Bastion:      ${BASTION_SUBNET_RANGE}"
```

<div id="04-create-cloud-nat">
  ## 04. Crear Cloud NAT
</div>

**File: `04-cloud-nat.sh`**

Los nodos privados de GKE requieren Cloud NAT para tener acceso saliente a Internet (por ejemplo, para descargar imágenes).

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "04. Creating Cloud NAT for Private Nodes"
echo "=========================================="

# Crear Cloud Router
echo "Creating Cloud Router..."
if gcloud compute routers describe clickhouse-router --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ Router already exists"
else
  gcloud compute routers create clickhouse-router \
    --network=${VPC_NAME} \
    --region=${GCP_REGION} \
    --project=${GCP_PROJECT}
  echo "   ✓ Router created"
fi

# Crear Cloud NAT
echo ""
echo "Creating Cloud NAT..."
if gcloud compute routers nats describe clickhouse-nat --router=clickhouse-router --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ NAT already exists"
else
  gcloud compute routers nats create clickhouse-nat \
    --router=clickhouse-router \
    --region=${GCP_REGION} \
    --nat-all-subnet-ip-ranges \
    --auto-allocate-nat-external-ips \
    --enable-logging \
    --log-filter=ERRORS_ONLY \
    --project=${GCP_PROJECT}
  echo "   ✓ NAT created"
fi

echo ""
echo "=========================================="
echo "✅ Cloud NAT Setup Complete!"
echo "=========================================="
echo ""
echo "Router: clickhouse-router"
echo "NAT:    clickhouse-nat"
echo "Region: ${GCP_REGION}"
```

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "06. Creating GCS Bucket"
echo "=========================================="

# Crear bucket
echo "Creating GCS bucket: ${BUCKET_NAME}..."
if gcloud storage ls gs://${BUCKET_NAME}/ --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ Bucket already exists"
else
  gcloud storage buckets create gs://${BUCKET_NAME} \
    --project=${GCP_PROJECT} \
    --default-storage-class=STANDARD \
    --location=${GCP_REGION} \
    --uniform-bucket-level-access

echo ""
echo "Enabling uniform bucket-level access..."
gcloud storage buckets update gs://${BUCKET_NAME} --uniform-bucket-level-access
echo "   ✓ Uniform access enabled"

# Otorgar permisos a la cuenta de servicio
echo ""
echo "Granting permissions to service account..."
gcloud storage buckets add-iam-policy-binding gs://${BUCKET_NAME} --member=serviceAccount:${GSA_EMAIL} --role=roles/storage.objectAdmin
gcloud storage buckets add-iam-policy-binding gs://${BUCKET_NAME} --member=serviceAccount:${GSA_EMAIL} --role=roles/storage.legacyBucketReader
echo "   ✓ Permissions granted"

echo ""
echo "=========================================="
echo "✅ GCS Bucket Setup Complete!"
echo "=========================================="
echo ""
echo "Bucket:   ${BUCKET_NAME}"
echo "Region:   ${GCP_REGION}"
echo "Endpoint: https://storage.googleapis.com"
```

**Archivo: `07-gke-cluster.sh`**

Crea un **clúster de GKE totalmente privado** para cumplir con FedRAMP:

* Los nodos worker solo tienen IP internas
* El plano de control tiene **solo un endpoint privado**
* Todo el acceso debe provenir de dentro de la VPC (a través del bastión)

```bash expandable
echo "07. Creating Private GKE Cluster"
echo "=========================================="

    --region=${GCP_REGION} \
    --node-locations=${GCP_ZONES} \
    --network=${VPC_NAME} \
    --subnetwork=${SUBNET_NAME} \
    --cluster-secondary-range-name=pods \
    --services-secondary-range-name=services \
    --enable-ip-alias \
    --enable-private-nodes \
    --enable-private-endpoint \
    --master-ipv4-cidr=${MASTER_IPV4_CIDR} \
    --enable-master-authorized-networks \
    --master-authorized-networks=${SUBNET_RANGE},${BASTION_SUBNET_RANGE} \

    --disk-type=pd-standard \
    --disk-size=50 \
    --project=${GCP_PROJECT}
  echo "   ✓ Cluster created"

# Obtener credenciales (debe ejecutarse desde dentro de la VPC / bastión)
echo ""
echo "Getting cluster credentials..."
gcloud container clusters get-credentials ${GKE_CLUSTER_NAME} \
  --region=${GCP_REGION} \
  --internal-ip \
  --project=${GCP_PROJECT}
echo "   ✓ Credentials configured"

echo "✅ Private GKE Cluster Ready!"
echo "=========================================="
```

<div id="09-local-ssd-daemonset">
  ## 09. Conjunto de daemon para SSD local
</div>

**Archivo: `09-local-ssd-daemonset.sh`**

GKE Container-Optimized OS (COS) tiene un sistema de archivos raíz de solo lectura, por lo que no podemos crear `/nvme`. En su lugar, montamos el SSD local en `/mnt/disks/ssd0` y configuramos ClickHouse para usar esa ruta.

**Nota:** GKE no permite `--metadata-from-file=startup-script` en los pools de nodos (clave reservada), por lo que se requiere un conjunto de daemon para formatear y montar el SSD local.

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "09. Desplegando conjunto de daemon de SSD local"
echo "=========================================="

kubectl apply -f - <<'EOF'
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: local-ssd-setup
  namespace: kube-system
spec:
  selector:
    matchLabels:
      app: local-ssd-setup
  template:
    metadata:
      labels:
        app: local-ssd-setup
    spec:
      hostPID: true
      nodeSelector:
        clickhouseGroup: server
      tolerations:
      - key: "clickhouse.com/do-not-schedule"
        operator: "Exists"
        effect: "NoSchedule"
      initContainers:
      - name: setup-ssd
        image: busybox:1.36
        command:
        - /bin/sh
        - -c
        - |
          set -e
          
          # Usar nsenter para ejecutar comandos en el host
          nsenter -t 1 -m -- /bin/sh -c '
            # Buscar dispositivo SSD local
            if [ -b /dev/disk/by-id/google-local-nvme-ssd-0 ]; then
              DEV=/dev/disk/by-id/google-local-nvme-ssd-0
            elif [ -b /dev/disk/by-id/google-local-ssd-0 ]; then
              DEV=/dev/disk/by-id/google-local-ssd-0
            else
              echo "No local SSD found"
              exit 0
            fi
            
            mkdir -p /mnt/disks/ssd0
            
            # Formatear si es necesario
            if ! blkid $DEV 2>/dev/null | grep -q ext4; then
              echo "Formatting $DEV..."
              mkfs.ext4 -F $DEV
            fi
            
            # Montar si es necesario
            if ! mountpoint -q /mnt/disks/ssd0; then
              echo "Mounting $DEV to /mnt/disks/ssd0..."
              mount $DEV /mnt/disks/ssd0
            fi
            chmod 755 /mnt/disks/ssd0
            
            echo "Local SSD ready at /mnt/disks/ssd0"
            df -h /mnt/disks/ssd0
          '
        securityContext:
          privileged: true
      containers:
      - name: pause
        image: gcr.io/google-containers/pause:3.2
EOF

echo ""
echo "Esperando a que el conjunto de daemon esté listo..."
sleep 15
kubectl get ds -n kube-system local-ssd-setup
kubectl get pods -n kube-system -l app=local-ssd-setup
kubectl logs -n kube-system -l app=local-ssd-setup -c setup-ssd

echo ""
echo "=========================================="
echo "✓ ¡Conjunto de daemon de SSD local desplegado!"
echo "=========================================="
echo ""
echo "IMPORTANTE: El SSD está montado en /mnt/disks/ssd0"
echo "Debe configurar ClickHouse para usar esta ruta"
echo "en lugar de /nvme/disk (GKE COS tiene sistema de archivos raíz de solo lectura)"
```

**Notas importantes:**

* GKE Container-Optimized OS tiene un **sistema de archivos raíz de solo lectura**; no se puede crear `/nvme`
* El SSD local está montado en `/mnt/disks/ssd0`
* Usa la imagen `busybox:1.36` (no se requiere conexión a Internet para `apt-get`)
* Usa `nsenter` para ejecutar comandos en el sistema de archivos del host
* El conjunto de daemon debe desplegarse **antes** del clúster de ClickHouse para evitar condiciones de carrera

<div id="14-create-fips-certificates-fips-only">
  ## 14. Crear certificados FIPS (solo FIPS)
</div>

**Archivo: `14-create-fips-certs.sh`** — Omite este paso si `ENABLE_FIPS=false`.

Los certificados conformes con FIPS deben generarse con algoritmos aprobados por FIPS en un entorno con FIPS habilitado. Este script ejecuta un pod de Kubernetes de Red Hat UBI8 en el clúster de GKE con la política criptográfica FIPS habilitada y, a continuación, copia los certificados generados de vuelta al host bastión mediante `kubectl cp`.

**Requisitos:**

* Tamaño mínimo de clave RSA de 3072 bits
* Algoritmo de firma SHA-256 o superior
* Los nombres alternativos del sujeto (SAN) deben incluir los nombres DNS del clúster
* Acceso con `kubectl` al clúster de GKE (no se requiere `docker`)

**Tipos de certificados:**

| Certificate | Files                                    | Purpose                            | SANs Required                                                                     |
| ----------- | ---------------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| CA          | `ca/ca.crt`, `ca/ca.key`                 | Autoridad certificadora            | N/A                                                                               |
| Server      | `server/server.crt`, `server/server.key` | Conexiones a clickhouse-server     | `*.c-${CLUSTER_NAME}-server-headless.ns-${CLUSTER_NAME}.svc.${KUBERNETES_DOMAIN}` |
| Client      | `client/client.crt`, `client/client.key` | Conexiones desde clickhouse-server | No se requiere ninguno                                                            |
| Keeper      | `keeper/keeper.crt`, `keeper/keeper.key` | Conexiones a clickhouse-keeper     | `*.c-${CLUSTER_NAME}-keeper-headless.ns-${CLUSTER_NAME}.svc.${KUBERNETES_DOMAIN}` |

El script realiza estos pasos:

1. Crea un ConfigMap con el script de generación de certificados
2. Ejecuta un pod de Kubernetes UBI8 con un initContainer que instala OpenSSL, establece la política criptográfica FIPS mediante `update-crypto-policies --set FIPS` y genera todos los certificados
3. Copia los certificados de vuelta al host bastión mediante `kubectl cp`
4. Elimina el pod de Kubernetes y el ConfigMap

Consulta `fips/14-create-fips-certs.sh` para ver el script completo.

**Notas importantes:**

* Los certificados caducan al cabo de 365 días de forma predeterminada; ajusta `CERT_VALIDITY` según sea necesario
* El certificado de CA caduca al cabo de 3650 días (10 años)
* Utiliza claves RSA de 3072 bits (el mínimo compatible con FIPS)
* Mantén seguras las claves privadas (archivos `*.key`) y nunca las subas al control de versiones

<div id="18-bind-workload-identity-to-helm-sa">
  ## 18. Vincular Workload Identity a la cuenta de servicio de Helm
</div>

**Archivo: `18-bind-helm-workload-identity.sh`**

El gráfico de Helm crea su propia cuenta de servicio (`ch-${CLUSTER_NAME}-sa`). Debe vincular Workload Identity a esta cuenta de servicio para acceder a GCS.

**Importante:** Los pods de Keeper y del servidor creados durante el paso 17 se inician *antes* de que exista esta vinculación de Workload Identity, por lo que fallarán con errores 403 Access Denied de GCS. Este script reinicia automáticamente los pods después de realizar la vinculación para que recojan las nuevas credenciales.

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "18. Vinculando Workload Identity a Helm SA"
echo "=========================================="

# Esperar a que se cree la SA de Helm
echo "Esperando a que se cree la cuenta de servicio de Helm..."
timeout=300
elapsed=0
while ! kubectl get serviceaccount ch-${CLUSTER_NAME}-sa -n ${NAMESPACE} &>/dev/null; do
  if [ $elapsed -ge $timeout ]; then
    echo "ERROR: Tiempo de espera agotado esperando la cuenta de servicio de Helm"
    exit 1
  fi
  sleep 5
  elapsed=$((elapsed + 5))
  echo "  Esperando... (${elapsed}s)"
done
echo "   ✓ Cuenta de servicio de Helm encontrada"

# Anotar la SA creada por helm
echo ""
echo "Anotando la cuenta de servicio de Helm..."
kubectl annotate serviceaccount ch-${CLUSTER_NAME}-sa \
  -n ${NAMESPACE} \
  iam.gke.io/gcp-service-account=${GSA_EMAIL} \
  --overwrite
echo "   ✓ Cuenta de servicio anotada"

# Vincular Workload Identity
echo ""
echo "Vinculando Workload Identity..."
gcloud iam service-accounts add-iam-policy-binding ${GSA_EMAIL} \
  --project=${GCP_PROJECT} \
  --role=roles/iam.workloadIdentityUser \
  --member="serviceAccount:${GCP_PROJECT}.svc.id.goog[${NAMESPACE}/ch-${CLUSTER_NAME}-sa]" \
  --quiet
echo "   ✓ Workload Identity vinculada"

echo ""
echo "Verificando anotación..."
kubectl get sa ch-${CLUSTER_NAME}-sa -n ${NAMESPACE} -o yaml | grep -A3 annotations

# Reiniciar los pods para que adopten las nuevas credenciales de Workload Identity.
# Los pods creados en el paso 17 se iniciaron antes de que existiera el vínculo, por lo que
# no tienen credenciales de GCP y fallarán con 403 en GCS.
echo ""
echo "Reiniciando los pods de keeper y servidor para adoptar Workload Identity..."
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=keeper --wait=false 2>/dev/null || true
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=server --wait=false 2>/dev/null || true
echo "   ✓ Pods reiniciándose"

echo ""
echo "Esperando a que los pods de keeper estén listos..."
kubectl wait --for=condition=ready pod \
  -l clickhouseGroup=keeper \
  -n ${NAMESPACE} \
  --timeout=600s
echo "   ✓ Pods de keeper listos"

echo ""
echo "Esperando a que se creen los pods de servidor..."
echo "   (El operador crea los servidores una vez que los keepers están en buen estado)"
timeout=600
elapsed=0
while ! kubectl get pods -n ${NAMESPACE} -l clickhouseGroup=server -o name 2>/dev/null | grep -q .; do
  if [ $elapsed -ge $timeout ]; then
    echo "ERROR: Tiempo de espera agotado esperando la creación de los pods de servidor"
    echo "  kubectl get pods -n ${NAMESPACE}"
    exit 1
  fi
  sleep 10
  elapsed=$((elapsed + 10))
  echo "  Esperando los pods de servidor... (${elapsed}s)"
done

echo "Esperando a que los pods de servidor estén listos..."
kubectl wait --for=condition=ready pod \
  -l clickhouseGroup=server \
  -n ${NAMESPACE} \
  --timeout=600s
echo "   ✓ Pods de servidor listos"

echo ""
echo "=========================================="
echo "✅ ¡Workload Identity vinculada a Helm SA!"
echo "=========================================="
echo ""
kubectl get pods -n ${NAMESPACE}
```

<div id="19-verify-installation">
  ## 19. Verificar la instalación
</div>

**Modo estándar** (sin TLS):

```bash
# Reenvío de puertos al puerto nativo de ClickHouse
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9000:9000 -n ${NAMESPACE} &

# Conectar con clickhouse-client
clickhouse client --host localhost --port 9000 --password "${CLICKHOUSE_PASSWORD}"
```

**Modo TLS (FIPS)** — Con `openSSL.required=true`, ClickHouse solo acepta conexiones en puertos seguros. Use el puerto **9440** (TLS nativo) en lugar del 9000:

```bash
# Reenvío de puertos al puerto nativo seguro de ClickHouse
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9440:9440 -n ${NAMESPACE} &

# Conectar con certificados autofirmados
clickhouse client --host localhost --port 9440 \
  --password "${CLICKHOUSE_PASSWORD}" \
  --secure \
  --accept-invalid-certificate
```

La opción `--accept-invalid-certificate` es necesaria porque usamos certificados autofirmados. En producción, si usa certificados válidos firmados por una CA, especifique explícitamente el certificado de la CA:

```bash
clickhouse client --host localhost --port 9440 \
  --password "${CLICKHOUSE_PASSWORD}" \
  --secure \
  --config-file <(cat <<'EOF'
<config>
    <openSSL>
        <client>
            <caConfig>./certs/ca/ca.crt</caConfig>
        </client>
    </openSSL>
</config>
EOF
)
```

**Ejecute una consulta de prueba:**

```sql
SELECT 1;
```

Resultado esperado:

```
   ┌─1─┐
1. │ 1 │
   └───┘
1 row in set. Elapsed: 0.001 sec.
```

**Importante (FIPS):** Los puertos 9000 (protocolo nativo en texto sin cifrar) y 8123 (HTTP en texto sin cifrar) rechazarán las conexiones cuando `openSSL.required=true`. Use en su lugar el puerto 9440 (TLS nativo) o 8443 (HTTPS).

<div id="appendix-fips-specific-considerations">
  ## Apéndice: Consideraciones específicas de FIPS
</div>

> **Nota:** Esta sección solo se aplica cuando `ENABLE_FIPS=true` está configurado en `00-env.sh`.

<div id="certificate-requirements">
  ### Requisitos de certificados
</div>

El cumplimiento de FIPS requiere:

* Claves RSA de al menos 3072 bits
* Algoritmos de firma aprobados por FIPS (SHA-256 o superior)
* Certificados generados en un entorno con FIPS habilitado (Red Hat UBI8)
* Validación correcta de la cadena de certificados

<div id="openssl-configuration">
  ### Configuración de OpenSSL
</div>

Tanto el servidor como Keeper deben tener:

* `openSSL.enabled=true` - Habilita TLS
* `openSSL.required=true` - Exige TLS (rechaza conexiones sin TLS)
* `openSSL.selfSigned=true` - Para certificados autofirmados (establece `false` si usas una CA válida)

<div id="key-differences-from-standard-gcp-installation">
  ### Diferencias clave respecto a la instalación estándar de GCP
</div>

| Configuración                       | Estándar        | FIPS                            |
| ----------------------------------- | --------------- | ------------------------------- |
| Etiqueta de imagen del servidor     | `25.8.1.9104`   | `25.8.1.9104-fips`              |
| Etiqueta de imagen de Keeper        | `25.10.1.6624`  | `26.1.1.1493`                   |
| OpenSSL habilitado                  | Sin configurar  | `true`                          |
| OpenSSL requerido                   | Sin configurar  | `true`                          |
| Certificados TLS                    | No obligatorios | Obligatorios (RSA de 3072 bits) |
| Puerto de conexión del cliente      | `9000` (nativo) | `9440` (TLS nativo)             |
| Puerto HTTP                         | `8123`          | `8443` (HTTPS)                  |
| Opción `--secure` del cliente       | No necesaria    | Obligatoria                     |
| Opción para certificado autofirmado | N/A             | `--accept-invalid-certificate`  |

<div id="certificate-verification-failures-fips">
  ### Errores de verificación de certificados (FIPS)
</div>

Si ve errores como &quot;certificate verify failed&quot;:

1. Verifique que el certificado de la CA sea correcto:

```bash
openssl x509 -in ${CERT_DIR}/ca/ca.crt -text -noout
```

2. Verifique los SAN del certificado del servidor:

```bash
openssl x509 -in ${CERT_DIR}/server/server.crt -text -noout | grep -A5 "Subject Alternative Name"
```

3. Compruebe el contenido del secreto:

```bash
kubectl get secret ${CLUSTER_NAME}-server-cert-secret -n ${NAMESPACE} -o yaml
```

<div id="fips-mode-verification">
  ### Verificación del modo FIPS
</div>

Verifique que los certificados generados cumplan con FIPS:

```bash
# Verificar el tamaño de la clave
openssl rsa -in ${CERT_DIR}/server/server.key -text -noout | grep "Private-Key"

# Verificar el algoritmo de firma
openssl x509 -in ${CERT_DIR}/server/server.crt -text -noout | grep "Signature Algorithm"
```

Debería mostrar:

* Clave privada: 3072 bits
* Algoritmo de firma: sha256WithRSAEncryption (o una versión superior)

<div id="gcs-access-denied-errors-403">
  ### Errores de acceso denegado a GCS (403)
</div>

La causa más común es una **condición de carrera de Workload Identity**: los pods se inician durante la instalación de Helm (paso 17) antes de que a la SA creada por Helm (`ch-${CLUSTER_NAME}-sa`) se le haya aplicado la vinculación de Workload Identity en el paso 18. El paso 18 ahora resuelve esto automáticamente reiniciando los pods después de aplicar la vinculación.

Si sigues viendo errores 403:

```bash
# 1. Verificar la anotación de Workload Identity en la SA creada por Helm
kubectl get sa ch-${CLUSTER_NAME}-sa -n ${NAMESPACE} -o yaml | grep -A5 annotations

# 2. Verificar el enlace IAM
gcloud iam service-accounts get-iam-policy ${GSA_EMAIL}

# 3. Verificar los permisos del bucket de GCS para la GSA
gcloud storage buckets get-iam-policy gs://${BUCKET_NAME} | grep ${GSA_EMAIL}

# 4. Probar desde dentro del pod (debe devolver el correo electrónico de la GSA)
kubectl exec -it <pod-name> -n ${NAMESPACE} -- curl -s -H "Metadata-Flavor: Google" \
  http://169.254.169.254/computeMetadata/v1/instance/service-accounts/default/email

# 5. Reiniciar los pods para aplicar las credenciales (si el paso 18 se ejecutó después de que los pods arrancaron)
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=keeper
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=server
```

<div id="connection-refused-on-port-9000-fips">
  ### Conexión rechazada en el puerto 9000 (FIPS)
</div>

Con TLS FIPS habilitado (`openSSL.required=true`), ClickHouse no acepta conexiones en texto plano. Los puertos 9000 (nativo) y 8123 (HTTP) rechazarán las conexiones. Use en su lugar los puertos seguros:

| Protocolo | Puerto sin cifrar | Puerto TLS |
| --------- | ----------------- | ---------- |
| Nativo    | 9000              | **9440**   |
| HTTP      | 8123              | **8443**   |

```bash
# Incorrecto - conexión rechazada
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9000:9000 -n ${NAMESPACE}
clickhouse client --host localhost --port 9000

# Correcto
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9440:9440 -n ${NAMESPACE}
clickhouse client --host localhost --port 9440 --secure --accept-invalid-certificate
```

<div id="validate-ssd-cache-script">
  ### Script para validar la caché SSD
</div>

`validate-ssd-cache.sh`

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "17. Validating SSD Cache Configuration"
echo "=========================================="

echo ""
echo "1. Checking DaemonSet status..."
DS_READY=$(kubectl get ds local-ssd-setup -n kube-system -o jsonpath='{.status.numberReady}')
DS_DESIRED=$(kubectl get ds local-ssd-setup -n kube-system -o jsonpath='{.status.desiredNumberScheduled}')

if [ "$DS_READY" = "$DS_DESIRED" ]; then
  echo "✅ DaemonSet ready: $DS_READY/$DS_DESIRED pods"
else
  echo "❌ DaemonSet not ready: $DS_READY/$DS_DESIRED pods"
  exit 1
fi

echo ""
echo "2. Checking ClickHouseCluster SSD configuration..."
SSD_CONFIG=$(kubectl get clickhousecluster c-${CLUSTER_NAME} -n ${NAMESPACE} -o jsonpath='{.spec.ssdCacheConfiguration}')

if echo "$SSD_CONFIG" | jq -e '.hostPathBaseDirectory == "/mnt/disks/ssd0/"' > /dev/null; then
  echo "✅ SSD cache configured in CRD:"
  echo "$SSD_CONFIG" | jq .
else
  echo "❌ SSD cache not properly configured"
  exit 1
fi

echo ""
echo "3. Waiting for server pods to be ready..."
kubectl wait --for=condition=ready pod \
  -l clickhouseGroup=server \
  -n ${NAMESPACE} \
  --timeout=300s

echo ""
echo "4. Checking pod volume mounts..."
SERVER_POD=$(kubectl get pods -n ${NAMESPACE} -l clickhouseGroup=server -o name | head -1)
echo "Checking pod: $SERVER_POD"

CACHE_MOUNT=$(kubectl get $SERVER_POD -n ${NAMESPACE} -o jsonpath='{.spec.containers[0].volumeMounts}' | jq '.[] | select(.name == "ch-cache-volume")')

if [ -n "$CACHE_MOUNT" ]; then
  echo "✅ Cache volume mounted:"
  echo "$CACHE_MOUNT" | jq .
else
  echo "❌ Cache volume not found in pod"
  exit 1
fi

echo ""
echo "5. Checking pod volume definition..."
CACHE_VOL=$(kubectl get $SERVER_POD -n ${NAMESPACE} -o jsonpath='{.spec.volumes}' | jq '.[] | select(.name == "ch-cache-volume")')

if [ -n "$CACHE_VOL" ]; then
  echo "✅ Cache volume defined:"
  echo "$CACHE_VOL" | jq .
else
  echo "❌ Cache volume not found in pod spec"
  exit 1
fi

echo ""
echo "6. Verifying cache is accessible inside container..."
if kubectl exec -n ${NAMESPACE} $SERVER_POD -- df -h /mnt/clickhouse-cache 2>/dev/null; then
  echo "✅ Cache directory accessible and mounted"
else
  echo "❌ Cache directory not accessible"
  exit 1
fi

echo ""
echo "7. Checking cache usage in ClickHouse..."
echo "Connecting to ClickHouse to verify cache configuration..."

# Construir las opciones de conexión del cliente
CLIENT_FLAGS=(--password="${CLICKHOUSE_PASSWORD}")
if [ "$ENABLE_FIPS" = "true" ]; then
  # En modo FIPS, OpenSSL es obligatorio: localice el certificado de la CA y configure TLS
  CA_CERT_PATH=$(kubectl exec -n ${NAMESPACE} $SERVER_POD -- \
    find /etc -name "ca.crt" -type f 2>/dev/null | head -1)
  if [ -z "$CA_CERT_PATH" ]; then
    echo "❌ Could not find CA cert inside container"
    exit 1
  fi
  echo "Using CA cert: $CA_CERT_PATH"

  CLIENT_FLAGS+=(--secure --config-file=/tmp/ch-client-ssl.xml)
  kubectl exec -n ${NAMESPACE} $SERVER_POD -- bash -c "cat > /tmp/ch-client-ssl.xml << EOF
<clickhouse>
  <openSSL>
    <client>
      <caConfig>${CA_CERT_PATH}</caConfig>
    </client>
  </openSSL>
</clickhouse>
EOF"
fi

# Consultar la configuración de la caché del sistema de archivos (la caché SSD es una capa de caché del sistema de archivos
# sobre los discos de ObjectStorage, por lo que aparece en system.filesystem_cache_settings
# en lugar de como un disco independiente en system.disks)
CACHE_INFO=$(kubectl exec -n ${NAMESPACE} $SERVER_POD -- clickhouse-client "${CLIENT_FLAGS[@]}" -q "
SELECT
    cache_name,
    path,
    formatReadableSize(max_size) as max_size,
    formatReadableSize(current_size) as current_size,
    current_elements_num,
    is_initialized
FROM system.filesystem_cache_settings
FORMAT Vertical
" 2>/dev/null) || true

if [ -n "$CACHE_INFO" ]; then
  echo "✅ Filesystem cache active in ClickHouse:"
  echo "$CACHE_INFO"
else
  echo "⚠️  Could not query ClickHouse cache info (cluster may still be initializing)"
fi

echo ""
echo "=========================================="
echo "✅ SSD Cache Validation Complete!"
echo "=========================================="
echo ""
echo "Summary:"
echo "  • DaemonSet mounted SSD at: /mnt/disks/ssd0 (on host)"
echo "  • Operator created volume:  ch-cache-volume"
echo "  • Container mount point:    /mnt/clickhouse-cache"
echo "  • Cache size configured:    ${CACHE_BYTES_PER_GI_RAM} per GiB RAM"
echo ""
echo "The SSD cache is fully configured and operational!"
```

<div id="security-best-practices">
  ## Mejores prácticas de seguridad
</div>

1. **Gestión de certificados** (FIPS)
   * Rote los certificados antes de su vencimiento (valor predeterminado: 365 días)
   * Almacene las claves privadas de forma segura (use gestión de secretos)
   * Nunca suba certificados al control de versiones
   * Use certificados adecuados firmados por una CA en producción

2. **Seguridad de red**
   * Use un clúster privado de GKE sin endpoint público
   * Restrinja `master-authorized-networks` al host bastión y a las subredes de GKE
   * Habilite los logs de flujo de VPC
   * Use Cloud NAT para un acceso saliente controlado

3. **Control de acceso**
   * Use Workload Identity en lugar de credenciales estáticas
   * Habilite RBAC de Kubernetes
   * Audite regularmente los logs de acceso
   * Use la suplantación de cuentas de servicio para la implementación

4. **Monitorización**
   * Supervise las fechas de vencimiento de los certificados (FIPS)
   * Configure alertas para conexiones TLS fallidas (FIPS)
   * Supervise los patrones de acceso de GCS
   * Habilite Cloud Audit Logging
