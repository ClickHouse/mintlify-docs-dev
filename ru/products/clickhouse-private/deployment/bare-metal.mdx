Ниже приведен пример процесса установки на bare-metal-узлах в AWS

<div id="terraform">
  ### Terraform
</div>

<div id="download-and-install-terraform">
  #### Скачайте и установите Terraform
</div>

```
dnf install -y unzip git
```

```
curl -O  https://releases.hashicorp.com/terraform/1.13.2/terraform_1.13.2_linux_amd64.zip
```

```
unzip terraform_1.13.2_linux_amd64.zip
```

```
sudo cp terraform /usr/local/bin
```

```
terraform version
```

```
Terraform v1.13.2
on linux_amd64
```

<div id="download-and-unzip-the-examples-scripts">
  #### Скачайте и распакуйте скрипты с примерами
</div>

`<<EXAMPLES_LINK>>`

```
unzip example-scripts.zip
cd ./bare-metal

```

<div id="acquire-aws-iam-credentials-and-create-a-credentials-file">
  #### Получите учетные данные AWS IAM и создайте файл с учетными данными
</div>

Перейдите в консоль AWS IAM, создайте ключ доступа и секретный ключ
и сохраните их значения.

**ПРИМЕЧАНИЕ**
Замените `<Your AWS ACCESS KEY ID>` и `<Your AWS SECRET ACCESS KEY>` на
значения, полученные в консоли AWS IAM.

```
cat > aws-creds.sh <<EOF
export AWS_ACCESS_KEY_ID=<Your AWS ACCESS KEY ID>
export AWS_SECRET_ACCESS_KEY=<Your AWS SECRET ACCESS KEY>
export AWS_REGION=us-east-2
EOF
```

<div id="load-your-aws-iam-credentials">
  #### Загрузите учетные данные AWS IAM
</div>

```
source ./aws-creds.sh
```

**ПРИМЕЧАНИЕ — добавьте `-migrate-state`, если переносите файл состояния из локального хранилища в S3**

<div id="initialize-the-rke2-terraform-module">
  #### Инициализируйте модуль Terraform rke2
</div>

```
terraform -chdir=modules/rke2 init \ 
-backend-config="encrypt=true" \
-backend-config="region=us-east-2" \
-backend-config="bucket=chb-tfstate-359774249275" \
-backend-config="use_lockfile=true" \
-backend-config="key=chb/rke2/terraform.tfstate"
```

<div id="issue-a-terraform-apply-command-to-bring-the-stack-up">
  #### Выполните команду `terraform apply`, чтобы развернуть стек
</div>

Находясь в каталоге `terraform` в Git-репозитории

```
terraform -chdir=modules/rke2 apply \
-var-file=../../vars/common.tfvars \
-var-file=../../vars/instances.tfvars \
-var-file=../../vars/rke2.tfvars
```

<div id="ansible">
  ### Ansible
</div>

<div id="run-ansible-to-provision-rke2-software">
  #### Запустите Ansible для развертывания ПО RKE2
</div>

<div id="go-to-ansible-directory">
  ##### Перейдите в каталог Ansible
</div>

```
cd ~/bare-metal/ansible
```

<div id="install-ansible-galaxy-role-lablabsrke2">
  ##### Установите роль [lablabs.rke2](https://galaxy.ansible.com/ui/standalone/roles/lablabs/rke2/)
</div>

```
ansible-galaxy role install lablabs.rke2
```

<div id="install-ansible-galaxy-collection-kubernetes-core">
  ##### Установите коллекцию [kubernetes-core](https://galaxy.ansible.com/ui/repo/published/kubernetes/core/) из Ansible Galaxy
</div>

```
ansible-galaxy collection install kubernetes.core
```

<div id="verify-that-the-nodes-are-ready">
  ##### Убедитесь, что узлы готовы
</div>

```
ansible all -i inventory.yml -a 'cloud-init status'
```

<div id="configure-nvmes">
  ##### Настройте NVMe-накопители
</div>

```
ansible-playbook -i inventory.yml disks_nvme.yml
```

<div id="run-rke2-playbook-ansiblerke2_playbook">
  ##### Запустите playbook RKE2 *../ansible/rke2_playbook*
</div>

```
ansible-playbook -i inventory.yml rke2_playbook.yml
```

<div id="run-3_helm_install_clickhousesh">
  ###### Запустите 3_helm_install_clickhouse.sh
</div>

Этот скрипт автоматизирует процесс установки/обновления Helm для основного кластера ClickHouse: загружает переменные и подготавливает values-файл.

```bash
  #!/bin/bash
  source ./set_helm_vars.sh
  
  # Подготовить временный файл значений, раскрыв переменные в my-dynamic-values.yaml.
  echo "Expanding YAML values from my-dynamic-values.yaml using envsubst..."
  TEMP_VALUES_FILE=$(mktemp) # Создать уникальный временный файл
  if ! envsubst < clickhouse-values.yaml > "$TEMP_VALUES_FILE"; then
      echo "Error: Failed to expand variables in my-dynamic-values.yaml using envsubst."
      rm -f "$TEMP_VALUES_FILE" # Удалить временный файл при ошибке
      exit 1
  fi
  
  # Создать пространство имен для кластера
  kubectl create namespace ns-$CLUSTER_NAME
  
  # Убедиться, что секрет docker registry актуален.
  kubectl create secret docker-registry all-icr-io --docker-server=359774249275.dkr.ecr.us-east-2.amazonaws.com --docker-username=AWS --docker-password=$(aws ecr get-login-password) -n ns-$CLUSTER_NAM
  
  echo "Performing helm install for release '$CLUSTER_NAME'..."
  if ! helm upgrade "$CLUSTER_NAME" \
    oci://$ECR_HOST/helm/onprem-clickhouse-cluster \
    --install --reuse-values \
    --version="$CHART_VERSION" \
    -n ns-$CLUSTER_NAME \
    --create-namespace \
    --values "$TEMP_VALUES_FILE" \
    --timeout 10m0s; then
      echo "Error: Helm upgrade failed. Please review the output above for details."
      rm -f "$TEMP_VALUES_FILE" # Удалить временный файл при ошибке
      exit 1
  fi
  
  echo "Helm install completed successfully!"
  
  # 5. Удалить временный файл значений.
  echo "Cleaning up temporary values file..."
  rm "$TEMP_VALUES_FILE"
  
  # 6. Отслеживать состояние подов для проверки результата обновления.
  echo "Monitoring pod status in namespace 'clickhouse-operator-system' (Ctrl+C to exit monitoring):"
  kubectl get pods -n clickhouse-operator-system -w
  
  echo "--- Helm Upgrade Process Complete ---"
```

<div id="sts_server_patchsh">
  ###### sts_server_patch.sh
</div>

Этот скрипт предназначен для внесения изменений в StatefulSet подов сервера ClickHouse. Он обеспечивает применение необходимого секрета для загрузки образов к серверным StatefulSet, что критически важно для получения образов контейнеров из приватных реестров, таких как IBM Cloud Container Registry. Он также включает обработку ошибок и сообщает пользователю, что для вступления изменений в силу требуется перезапуск пода.

```bash
#!/bin/bash
# Немедленно завершить выполнение, если команда вернула ненулевой код.
set -euo pipefail

# --- Конфигурация и валидация ---
# Пространство имен и имя секрета передаются в качестве аргументов.

if [ "$#" -ne 2 ]; then
  echo "Usage: $0 <NAMESPACE> <IMAGE_PULL_SECRET_NAME>"
  echo "Example: $0 ns-my-cluster all-icr-io"
  exit 1
fi

TARGET_NAMESPACE="$1"
SECRET_NAME="$2"

# --- Логика скрипта ---

echo "--> Verifying secret '$SECRET_NAME' in namespace '$TARGET_NAMESPACE'..."
# 'set -e' завершит выполнение скрипта, если секрет не найден.
kubectl get secret "$SECRET_NAME" -n "$TARGET_NAMESPACE" >/dev/null
echo "    Secret found. Proceeding."

echo "--> Finding StatefulSets containing 'server' in their name..."
# Используется более надёжный jsonpath-запрос для получения имён напрямую.
# '|| true' гарантирует, что скрипт не завершится с ошибкой, если StatefulSets не найдены.
STS_LIST=$(kubectl get sts -n "$TARGET_NAMESPACE" --no-headers -o custom-columns=NAME:.metadata.name | grep "server" || true)

if [ -z "$STS_LIST" ]; then
  echo "    No matching 'server' StatefulSets found. Nothing to patch."
  exit 0
fi

echo "--> Found the following StatefulSets to patch:"
echo "$STS_LIST"

PATCH_JSON='{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"'"$SECRET_NAME"'"}]}}}}'

for STS_NAME in $STS_LIST; do
  echo "    - Patching ${STS_NAME}..."
  # Применить патч к StatefulSet. Перенаправить вывод в /dev/null для чистоты журналов.
  kubectl patch sts "$STS_NAME" -n "$TARGET_NAMESPACE" -p "$PATCH_JSON" >/dev/null
done

echo
echo "--> Patching process complete."
echo "--> IMPORTANT: Pods must be restarted for the new imagePullSecrets to take effect."
echo "    Example: kubectl delete pod <pod-name> -n ${TARGET_NAMESPACE}"
```

</div>

Если в журналах контейнера возникают ошибки Access Denied, связанные с S3 (например, у Keeper), возможно, потребуется передать учетные данные S3 через переменные окружения пода. Вместо kubectl edit можно использовать kubectl patch с YAML-файлом.

Пример ошибки:

```bash
2025.07.10 20:12:36.893641 [ 1 ] {} <Error> Application: Code: 499. DB::Exception: Message: Access Denied, bucket ch-s3-bb1bf91e-0eae-4d02-a842-e75d660d62bc, key ch-s3-00000000-0000-0000-0000-000000000000/keepers/0/log/clickhouse_access_check_eacdcaed-ef86-488c-ae77-22a7ec0db795, object size 4: While checking access for disk s3_keeper_log_disk. (S3_ERROR), Stack trace (when copying this message, always include the lines below): 
```

Создайте файл с именем sts&#95;keeper&#95;patch.yaml со следующим содержимым, заменив YOUR&#95;KEY и YOUR&#95;SECRET своими фактическими учетными данными AWS:

```yaml
apiVersion: apps/v1 
kind: StatefulSet 
metadata: 
  name: c-default-xx-01-keeper 
  namespace: ns-default-xx-01 
spec: 
  template: 
    spec: 
      containers: 
        - name: c-default-xx-01-keeper 
          env: 
          - name: AWS_ACCESS_KEY_ID 
            value: YOUR_KEY # Замените на ваш AWS Access Key ID 
          - name: AWS_SECRET_ACCESS_KEY 
            value: YOUR_SECRET # Замените на ваш AWS Secret Access Key 
```

Затем примените патч:

```bash
kubectl patch sts c-default-xx-01-keeper -n ns-default-xx-01 --patch-file sts_keeper_patch.yaml 
```

После внесения изменений следите за подами. Возможно, потребуется удалить проблемный под, чтобы принудительно пересоздать его с новой конфигурацией:

```bash
kubectl delete pod c-default-xx-01-keeper-0 -n ns-default-xx-01 
```

Скопируйте kubectl Secret в другое пространство имен (при необходимости)

Если ваш Secret kubectl нужно скопировать в другое пространство имен (например, из default в clickhouse-operator-system), используйте следующую команду. Обычно это уже делается скриптами.

```bash
kubectl get secret all-icr-io -n default -o yaml | \ 
  sed 's/namespace: default/namespace: clickhouse-operator-system/g' | \ 
  sed 's/ creationTimestamp: .*//g' | \ 
  sed 's/  resourceVersion: .*//g' | \ 
  sed 's/  uid: .*//g' | \ 
  kubectl apply -f - 
```

Удалите закэшированные образы контейнеров на узлах, чтобы проверить, что `imagePullSecrets` работают; иначе это будет иметь значение только при первом запуске на узле. 

<div id="run-script-remove_cached_imagessh">
  ##### Запустите скрипт remove_cached_images.sh
</div>

```bash
#!/bin/bash 
set -e 
 
echo "Starting cleanup process on all nodes..." 
echo "-----------------------------------" 
 
kubectl get nodes -o name | while read -r node_ref; do 
  node_name="${node_ref}" 
 
  echo "--> Processing $node_name" 
 
  # Шаг 1: Выполнить команду отладки и записать ВСЕ выходные данные в переменную. 
  # Конструкция '2>&1' обеспечивает перенаправление стандартного вывода и ошибок в одну переменную. 
  CMD_OUTPUT=$(kubectl debug $node_ref  \ 
    -n default -it --image=busybox --profile=general \ 
    -- sh -c 'chroot /host crictl rmi --all' 2>&1) 
 
  # Шаг 2: Вывести только строки, начинающиеся с "Creating" или "Deleted". 
  # Флаг '-E' включает расширенные регулярные выражения для оператора '|' (ИЛИ). 
  # Символ '^' привязывает совпадение к началу строки. 
  echo "$CMD_OUTPUT" | grep -E '^Creating|^Deleted' 
 
  # Шаг 3: Разобрать полный вывод для поиска имени пода, подлежащего удалению. 
  captured_pod_name=$(echo "$CMD_OUTPUT" | grep "Creating debugging pod" | awk '{print $4}') 
   
  if [ -n "$captured_pod_name" ]; then 
    echo "Cleaning up pod: $captured_pod_name" 
    kubectl delete pod "$captured_pod_name" -n default --wait=false 
  else 
    echo "    Warning: Could not determine pod name for node $node_name." 
  fi 
 
  echo "-----------------------------------" 
done 
 
echo "All nodes have been processed." 
```
