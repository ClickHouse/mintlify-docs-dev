<div id="zone-details-couldnt-be-found-for-any-pv">
  ### не удалось найти сведения о зоне ни для одного PV?
</div>

Если эта ошибка появляется в журнале оператора ClickHouse, это значит, что он не может завершить сверку состояния кластера ClickHouse, потому что ожидает, что topology-aware правила node affinity будут автоматически проставлены для PersistentVolume. В частности, оператор ищет node affinity на основе метки `topology.kubernetes.io/zone`. Обычно это обеспечивают провиженеры томов с поддержкой топологии (например, при использовании провиженера томов AWS EBS).

Однако у некоторых облачных провайдеров (например, IBM) или в средах в собственной инфраструктуре эти значения не заполняются автоматически либо используются нестандартные метки. Чтобы оператор всё же мог продолжить работу, рекомендуется добавить node affinity в StorageClass, например:

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-nvme-sc
allowVolumeExpansion: true
parameters:
  path: /nvme/disk
provisioner: rancher.io/local-path
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
allowedTopologies:
  - matchLabelExpressions:
      - key: topology.kubernetes.io/zone
        values:
          - <your_cluster_name>-keeper
          - <your_host_1>
          - <your_host_2>
          - <your_host_3>
          - <your_host_4>
          - <your_host_5>
          - <your_host_6>
      - key: directpv.min.io/zone
        values:
          - default
```

Это гарантирует, что тома хранилища будут созданы с правильной привязкой к узлам. Например:

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  ...
spec:
  accessModes:
    - ReadWriteOnce
  ...
  nodeAffinity:
    required:
      nodeSelectorTerms:
        - matchExpressions:
            - key: directpv.min.io/zone
              operator: In
              values:
                - default
  ...
```

Если для описания топологии используются нестандартные метки, оператор предоставляет свойство `additionalZoneLabelRegexes`. Например, если вы используете Helm-чарт для установки оператора, можно задать значение `operator.additionalZoneLabelRegexes` в helm равным `directpv.*zone`, чтобы оно соответствовало указанному выше PersistentVolume.

<div id="what-does-the-loadbalancertype-field-on-the-clickhousecluster-crd-do">
  ### Что делает поле `loadBalancerType` в CRD ClickHouseCluster?
</div>

`loadBalancerType` на самом деле не добавляет annotations балансировщика нагрузки в Service кластера ClickHouse. В настоящее время оператор ClickHouse не поддерживает создание балансировщика нагрузки для кластера ClickHouse. Это поле имеет назначение только в ClickHouse Cloud, где оно используется для создания пользователей в Cloud SQL Console.

<div id="do-i-have-to-use-a-nvme-attached-instance-what-purpose-does-the-nvme-disk-serve">
  ### Нужно ли использовать экземпляр с подключённым NVMe? Для чего нужен диск NVMe?
</div>

Диск NVMe используется оператором ClickHouse для монтирования тома кэша в подах сервера ClickHouse. Этот том используется для кэширования данных, поступающих из S3 (или аналогичных объектных хранилищ). Оператор автоматически настраивает диски в конфигурации сервера ClickHouse:

```yaml
s3diskWithCache:
    type: cache
    disk: s3disk
    path: /mnt/ClickHouse-cache/sharedS3DiskCache
    max_size:
    '@from_env': CONFIG_DISK_CACHE_SIZE
    cache_on_write_operations: 1
```

Обратите внимание: при использовании SharedMergeTree ClickHouse фактически не хранит данные локально. Локальное хранилище в этом случае нужно только для оптимизации производительности запросов к SharedMergeTree.

Можно использовать и другие устройства хранения, например AWS EBS при работе с экземплярами EC2. В этом случае несколько шагов в руководстве по онбордингу изменятся:

* Нужно убедиться, что диски подключены к экземплярам, на которых размещаются Kubernetes-поды сервера ClickHouse
* Шаблон запуска нужно изменить с учётом новой дисковой архитектуры. По-прежнему можно создать RAID-массив и отформатировать диск в ext4 или xfs, но устройства, разумеется, придётся перечислять с помощью другого инструмента (например, lsblk).
* Если диски смонтированы не в `/nvme/disk`, как в примере шаблона запуска, параметр `hostPathBaseDirectory` в Helm-чарте ClickHouseCluster нужно указать равным фактической точке монтирования.

Обратите внимание, что в зависимости от выбранной конфигурации производительность запросов может измениться.
