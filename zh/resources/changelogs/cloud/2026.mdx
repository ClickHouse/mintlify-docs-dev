<div id="clickstack-cloud">
  ### ClickStack Cloud 私有预览
</div>

ClickStack Cloud 是一个基于 ClickHouse Cloud 构建的完全托管、无服务器可观测性平台。团队可以将 OpenTelemetry 数据发送到托管端点，无需自行运维可观测性基础设施，即可立即浏览日志、指标和链路追踪。现已在 AWS us-east-1 区域开放私有预览。更多详情请阅读[博客文章](https://clickhouse.com/blog/clickstack-cloud-private-preview)，并加入[候补名单](https://clickhouse.com/cloud/clickstack-cloud-waitlist)以获取访问权限。

<div id="ai-notebooks-clickstack">
  ### 托管 ClickStack 的 AI Notebooks (Beta)
</div>

AI Notebooks 现已在托管 ClickStack 中以 Beta 版提供，为 SRE 和工程团队提供可持久保存且透明的工作区，用于开展 AI 辅助的事件调查。Notebooks 支持由提示词、查询、图表、推理步骤和调查结论组成的结构化序列，并支持通过分支工作流探索多种假设。更多详情请参阅[文档](/zh/clickstack/notebooks)。

<div id="clickstack-mcp-server">
  ### ClickStack MCP Server
</div>

全新开源的 ClickStack MCP Server 为外部 AI 智能体提供了基于 ClickStack 和 ClickHouse 构建的结构化可观测性调查工具。它提供了面向日志、指标和链路追踪的语义化调查原语，以及用于创建仪表盘、保存搜索和告警的双向编排原语。更多详情请参阅[文档](/zh/clickstack/mcp)和[博客文章](https://clickhouse.com/blog/observability-mcp-server-ai-notebooks#clickstack-mcp-server)。

<div id="executable-udfs">
  ### Executable UDFs (Public Beta)
</div>

Executable UDFs 现已在 ClickHouse Cloud 上进入 Public Beta。您可以使用 Python 编写函数，将其上传到集群中，并像调用任何内置函数一样在 SQL 中调用。ClickHouse 会运行一组长期存活的沙箱进程，并以查询级速度让数据行流经这些进程，因此您可以在任何支持 SQL 的地方使用自己的函数——包括临时查询、JOIN，甚至是每次 insert 时都会触发的 materialized view。更多详情，请阅读[公告博客](https://clickhouse.com/blog/executable-udfs-clickhouse-cloud-beta)。

<div id="clickpipes-gcp-native">
  ### ClickPipes 原生运行于 GCP
</div>

对于所有托管在 GCP 上的新建 ClickHouse Cloud 服务 (5 月 26 日之后创建) ，ClickPipes 基础设施现已原生运行于 GCP，并支持 Private Service Connect (PSC)。这消除了跨云出口费用，支持 GCP 原生私有网络，降低了延迟，并提供数据本地性保障。请参阅[受支持的 GCP 区域列表](/zh/integrations/clickpipes#list-of-static-ips)。

<div id="clickpipes-pubsub">
  ### 用于 GCP Pub/Sub 的 ClickPipes (私有预览)
</div>

ClickPipes 现已支持将 GCP Pub/Sub topic 中的流式数据直接导入 ClickHouse Cloud。该功能目前处于私有预览阶段——可[注册](https://clickhouse.com/cloud/clickpipes#pubsub-private-preview)申请访问。更多详情请参阅[文档](/zh/integrations/clickpipes/pubsub)。

<div id="clickhouse-agents">
  ### ClickHouse 智能体 — 智能体驱动分析 (Public Beta)
</div>

ClickHouse 智能体现已进入 Public Beta——这是一个由 Claude 驱动的官方智能体分析界面，让用户能够围绕其 ClickHouse 数据构建、运行和编排智能体。其功能包括具备 schema 感知能力的对话式分析、支持 MCP 的 AgentBuilder、子智能体拓扑以及代码生成。可在 [ai.clickhouse.cloud](https://ai.clickhouse.cloud) 使用。

<div id="clickhouse-postgres">
  ### ClickHouse Postgres (Public Beta)
</div>

基于本地 NVMe 存储的全托管 Postgres 现已进入 Public Beta，TPS 可达 AWS RDS 的 5 倍以上。原生 CDC (变更数据捕获) 管道可将数据直接流式传输到 ClickHouse，无需任何中间基础设施。开源 pg&#95;clickhouse 扩展让开发者能够在标准 Postgres 会话中查询 ClickHouse 表。阅读[博客文章](https://clickhouse.com/blog/postgres-managed-by-clickhouse-beta)了解更多详情。

<div id="horizontal-autoscaling">
  ### 水平自动扩缩容 (私有预览)
</div>

水平自动扩缩容会根据 ClickHouse Cloud 集群中的并发查询数自动调整副本数量：需求激增时横向扩容，负载下降时横向缩容。该功能目前以私有预览形式向使用 ClickHouse 26.2+ 的 Enterprise 和 Scale 层级客户开放。如需启用，请提供您的组织 ID 并联系支持团队。

<div id="postgres-query-insights">
  ### Postgres Query insights (私有预览)
</div>

[ClickHouse Cloud Managed Postgres](/zh/products/managed-postgres/overview) (私有预览) 现已新增 **Query insights** 选项卡。它会按影响程度对每种查询模式进行排名，并在以下三个界面中说明每种模式为何变慢：

* **Overview** — 在单个页面中查看数据库健康状况
* **Patterns** — 可按运行时间、CPU、错误和 P95 排序的表
* **各模式的弹出面板** — 延迟百分位、CPU 与 I/O、缓存与磁盘、临时落盘、并行工作线程不足，以及 WAL 量

由开源 Postgres 扩展 [pg&#95;stat&#95;ch](https://github.com/ClickHouse/pg_stat_ch) 提供支持。

<div id="centralized-marketplace-billing">
  ### 集中式 Marketplace 计费
</div>

客户现在可以通过单个云 Marketplace 订阅 (AWS、Azure 和 GCP) 统一整合多个组织的计费。主要更新包括：

* **Marketplace 订阅共享：**可将某个组织的计费方式从信用卡切换为另一个组织现有的 Marketplace 订阅，无需再额外开通新的 Marketplace 订阅。只有 PAYG 用量会被合并计费 (不包括预付费额度) 。
* **更新 Marketplace 订阅：**可将某个组织的 Marketplace 订阅更换为另一个组织正在使用的订阅。
* **备用付款方式：**使用 Marketplace 计费的组织现在可以添加信用卡作为后备付款方式，以便在主 Marketplace 订阅被取消或到期时使用。

更多详细信息，请参阅[计费文档](/zh/products/cloud/reference/billing/managing-payment-methods)。

<div id="april-3-2026">
  ## 2026 年 4 月 3 日
</div>

* **采用双窗口 recommender 的更智能自动扩缩容：** ClickHouse Cloud 现在在纵向自动扩缩容中采用双回看窗口机制，以 3 小时的“小窗口”和 30 小时的“大窗口”组合，替代此前单一的 30 小时窗口。这样可将缩容延迟从最长 30 小时缩短至最短 3 小时，在不牺牲扩容响应速度的前提下，降低波动性工作负载的基础设施成本。更多详情请阅读[博客文章](https://clickhouse.com/blog/smarter-auto-scaling)。
* **Cloud Console 中的 Monitoring：** 新增的概览和基础设施仪表盘可让您更清楚地了解 ClickHouse 服务器的行为。使用 ClickHouse Cloud 时，Admin 用户现在还会在出现常见问题时收到电子邮件通知。更多详情请阅读[博客文章](https://clickhouse.com/blog/clickhouse-cloud-new-monitoring-capabilities)。
* **Compute-compute separation (仓库) ：** 主服务 (也称为 parent 服务) 的自动闲置支持现已开始逐步开放公开预览。如果您的组织尚未启用此功能，请[联系支持团队](https://clickhouse.com/support/program)以获取访问权限。该功能进入正式可用后，默认行为将是：现有主服务可选择开启自动闲置，而新建主服务将默认启用该功能。
* **数据目录集成：** ClickHouse Cloud 现已支持在数据源 UI 中将 Iceberg REST Catalog 和 Microsoft OneLake 作为数据湖 catalog 集成。连接后，catalog 会显示为一个数据库，使您能够直接读取 Iceberg 表，而无需复制数据。
* **Google Cloud 上的自备 Cloud (BYOC) 现已正式可用：** ClickHouse BYOC 现已在 Google Cloud 上 GA，允许您在自己的 GCP 项目中部署 ClickHouse 服务，并满足严格的数据驻留要求。更多详情请阅读[文档](/zh/products/cloud/guides/infrastructure/deployment-options/byoc/overview)和[博客文章](https://clickhouse.com/blog/byoc-gcp-ga)。您也可以[联系我们](https://clickhouse.com/cloud/bring-your-own-cloud)申请访问权限。
* **预付费额度和付款方式变更通知：** ClickHouse Cloud 现在会在签订承诺合同后为您的组织添加预付费额度时，或在付款方式更新时 (信用卡或 Marketplace 订阅) 发送通知。通知默认通过 UI 和电子邮件发送，也可配置为同时发送到 Slack。
