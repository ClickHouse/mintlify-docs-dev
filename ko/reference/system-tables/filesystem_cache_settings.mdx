<div id="description">
  ## 설명
</div>

모든 파일 시스템 캐시 설정에 대한 정보가 포함되어 있습니다.

<div id="columns">
  ## 컬럼
</div>

{/*AUTOGENERATED_START*/}

* `cache_name` ([String](/ko/reference/data-types)) — 캐시 이름
* `path` ([String](/ko/reference/data-types)) — 캐시 디렉터리 경로
* `max_size` ([UInt64](/ko/reference/data-types)) — 최대 캐시 크기
* `max_elements` ([UInt64](/ko/reference/data-types)) — 캐시 요소의 최대 개수(예: 파일 세그먼트, 파일 시스템의 파일 수 제한)
* `max_file_segment_size` ([UInt64](/ko/reference/data-types)) — 단일 파일 세그먼트의 최대 크기
* `boundary_alignment` ([UInt64](/ko/reference/data-types)) — 파일 세그먼트 정렬
* `cache_on_write_operations` ([UInt8](/ko/reference/data-types)) — 라이트스루 캐시를 활성화합니다(INSERT 및 MERGE 시 캐시)
* `cache_policy` ([String](/ko/reference/data-types)) — 캐시 축출 정책
* `slru_size_ratio` ([Float64](/ko/reference/data-types)) — 보호 요소와 probationary 요소 간 SLRU 캐시 정책 크기 비율
* `background_download_threads` ([UInt64](/ko/reference/data-types)) — 백그라운드 다운로드 스레드 수. 값이 0이면 백그라운드 다운로드가 비활성화됩니다
* `background_download_queue_size_limit` ([UInt64](/ko/reference/data-types)) — 백그라운드 다운로드 큐 크기. 값이 0이면 백그라운드 다운로드가 비활성화됩니다
* `background_download_max_file_segment_size` ([UInt64](/ko/reference/data-types)) — 백그라운드 다운로드로 다운로드할 수 있는 최대 크기
* `load_metadata_threads` ([UInt64](/ko/reference/data-types)) — 서버 시작 시 캐시 메타데이터를 로드하는 데 사용되는 최대 스레드 수
* `load_metadata_asynchronously` ([UInt8](/ko/reference/data-types)) — 서버 시작 시 메타데이터를 비동기로 로드하도록 활성화합니다
* `keep_free_space_size_ratio` ([Float64](/ko/reference/data-types)) — 캐시가 백그라운드에서 유지하려는 여유 공간 비율
* `keep_free_space_elements_ratio` ([Float64](/ko/reference/data-types)) — 캐시가 백그라운드에서 유지하려는 여유 요소 비율
* `keep_free_space_remove_batch` ([UInt64](/ko/reference/data-types)) — 여유 공간/요소 비율을 유지하는 백그라운드 스레드가 한 번에 제거하는 캐시 요소 수
* `enable_filesystem_query_cache_limit` ([UInt8](/ko/reference/data-types)) — 쿼리 내에서 쓸 수 있는 캐시의 최대 크기 제한을 활성화합니다
* `cache_hits_threshold` ([UInt64](/ko/reference/data-types)) — 더 이상 사용이 권장되지 않는 설정
* `enable_bypass_cache_with_threshold` ([UInt8](/ko/reference/data-types)) — 문서화되지 않았습니다. 사용을 권장하지 않습니다
* `bypass_cache_threshold` ([UInt64](/ko/reference/data-types)) — 문서화되지 않았습니다. 사용을 권장하지 않습니다
* `write_cache_per_user_id_directory` ([UInt8](/ko/reference/data-types)) — 내부 ClickHouse Cloud 설정
* `allow_dynamic_cache_resize` ([UInt8](/ko/reference/data-types)) — 파일 시스템 캐시의 동적 크기 조정을 허용합니다
* `dynamic_resize_lock_wait_ms` ([UInt64](/ko/reference/data-types)) — 크기 조정 시도를 스키핑하기 전에 동적 크기 조정용 exclusive lock을 획득하기 위해 대기하는 제한 시간(밀리초)
* `max_size_ratio_to_total_space` ([Float64](/ko/reference/data-types)) — 전체 디스크 공간 대비 `max_size` 비율
* `skip_cache_on_disk_failure` ([UInt8](/ko/reference/data-types)) — true이면 디스크 IO 오류 발생 시 파일 시스템 캐시 작업을 자동으로 우회합니다. false(기본값)이면 디스크 IO 오류가 시작 실패로 전파됩니다.
* `use_split_cache` ([UInt8](/ko/reference/data-types)) — 파일을 system/data로 분리해 사용합니다.
* `split_cache_ratio` ([Float64](/ko/reference/data-types)) — split&#95;cache에서 전체 캐시 크기 대비 system 세그먼트의 비율
* `overcommit_eviction_evict_step` ([UInt64](/ko/reference/data-types)) — 오버커밋 축출 정책의 바이트 단위 축출 간격. keep&#95;free&#95;space&#95;*&#95;ratio 설정에 사용됩니다
* `check_cache_probability` ([Float64](/ko/reference/data-types)) — debug 또는 새니타이저 build에서만 동작합니다. 전체 캐시를 순회하며 각 캐시 요소의 상태를 확인해 캐시 정확성을 검사합니다
* `is_initialized` ([UInt8](/ko/reference/data-types)) — 캐시가 성공적으로 초기화되었는지 나타냅니다
* `current_size` ([UInt64](/ko/reference/data-types)) — 현재 캐시 크기
* `current_elements_num` ([UInt64](/ko/reference/data-types)) — 현재 캐시 요소(파일 세그먼트) 수
