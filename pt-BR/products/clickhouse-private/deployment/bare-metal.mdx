A seguir, um exemplo do processo de instalação em nós bare metal na AWS

<div id="terraform">
  ### Terraform
</div>

<div id="download-and-install-terraform">
  #### Baixe e instale o Terraform
</div>

```
dnf install -y unzip git
```

```
curl -O  https://releases.hashicorp.com/terraform/1.13.2/terraform_1.13.2_linux_amd64.zip
```

```
unzip terraform_1.13.2_linux_amd64.zip
```

```
sudo cp terraform /usr/local/bin
```

```
terraform version
```

```
Terraform v1.13.2
on linux_amd64
```

<div id="download-and-unzip-the-examples-scripts">
  #### Baixe e descompacte os scripts de exemplo
</div>

`<<EXAMPLES_LINK>>`

```
unzip example-scripts.zip
cd ./bare-metal

```

<div id="acquire-aws-iam-credentials-and-create-a-credentials-file">
  #### Obtenha credenciais do AWS IAM e crie um arquivo de credenciais
</div>

Acesse o console do AWS IAM, crie uma chave de acesso e uma chave secreta
e salve esses valores.

**NOTA**
Substitua `<Your AWS ACCESS KEY ID>` e `<Your AWS SECRET ACCESS KEY>` pelos
valores obtidos no console do AWS IAM.

```
cat > aws-creds.sh <<EOF
export AWS_ACCESS_KEY_ID=<Your AWS ACCESS KEY ID>
export AWS_SECRET_ACCESS_KEY=<Your AWS SECRET ACCESS KEY>
export AWS_REGION=us-east-2
EOF
```

<div id="load-your-aws-iam-credentials">
  #### Carregue suas credenciais do IAM da AWS
</div>

```
source ./aws-creds.sh
```

**OBSERVAÇÃO - Adicione `-migrate-state` se estiver migrando o estado do armazenamento local para o S3**

<div id="initialize-the-rke2-terraform-module">
  #### Inicialize o módulo Terraform do rke2
</div>

```
terraform -chdir=modules/rke2 init \ 
-backend-config="encrypt=true" \
-backend-config="region=us-east-2" \
-backend-config="bucket=chb-tfstate-359774249275" \
-backend-config="use_lockfile=true" \
-backend-config="key=chb/rke2/terraform.tfstate"
```

<div id="issue-a-terraform-apply-command-to-bring-the-stack-up">
  #### Execute o comando `terraform apply` para colocar a stack em funcionamento
</div>

De dentro do diretório `terraform`, localizado no repositório Git

```
terraform -chdir=modules/rke2 apply \
-var-file=../../vars/common.tfvars \
-var-file=../../vars/instances.tfvars \
-var-file=../../vars/rke2.tfvars
```

<div id="ansible">
  ### Ansible
</div>

<div id="run-ansible-to-provision-rke2-software">
  #### Execute o Ansible para provisionar o RKE2
</div>

<div id="go-to-ansible-directory">
  ##### Acesse o diretório do Ansible
</div>

```
cd ~/bare-metal/ansible
```

<div id="install-ansible-galaxy-role-lablabsrke2">
  ##### Instale a role do Ansible Galaxy [lablabs.rke2](https://galaxy.ansible.com/ui/standalone/roles/lablabs/rke2/)
</div>

```
ansible-galaxy role install lablabs.rke2
```

<div id="install-ansible-galaxy-collection-kubernetes-core">
  ##### Instale a coleção [kubernetes-core](https://galaxy.ansible.com/ui/repo/published/kubernetes/core/) do Ansible Galaxy
</div>

```
ansible-galaxy collection install kubernetes.core
```

<div id="verify-that-the-nodes-are-ready">
  ##### Verifique se os nós estão prontos
</div>

```
ansible all -i inventory.yml -a 'cloud-init status'
```

<div id="configure-nvmes">
  ##### Configure as unidades NVMe
</div>

```
ansible-playbook -i inventory.yml disks_nvme.yml
```

<div id="run-3_helm_install_clickhousesh">
  ###### Execute 3_helm_install_clickhouse.sh
</div>

Este script automatiza o processo de instalação/atualização com Helm do cluster principal do ClickHouse, carregando as variáveis e preparando o arquivo de valores.

```bash
  #!/bin/bash
  source ./set_helm_vars.sh
  
  # Prepara um arquivo de valores temporário expandindo variáveis em my-dynamic-values.yaml.
  echo "Expanding YAML values from my-dynamic-values.yaml using envsubst..."
  TEMP_VALUES_FILE=$(mktemp) # Cria um arquivo temporário único
  if ! envsubst < clickhouse-values.yaml > "$TEMP_VALUES_FILE"; then
      echo "Error: Failed to expand variables in my-dynamic-values.yaml using envsubst."
      rm -f "$TEMP_VALUES_FILE" # Remove o arquivo temporário em caso de erro
      exit 1
  fi
  
  # Cria o namespace para o cluster
  kubectl create namespace ns-$CLUSTER_NAME
  
  # Garante que o secret do docker registry esteja atualizado.
  kubectl create secret docker-registry all-icr-io --docker-server=359774249275.dkr.ecr.us-east-2.amazonaws.com --docker-username=AWS --docker-password=$(aws ecr get-login-password) -n ns-$CLUSTER_NAM
  
  echo "Performing helm install for release '$CLUSTER_NAME'..."
  if ! helm upgrade "$CLUSTER_NAME" \
    oci://$ECR_HOST/helm/onprem-clickhouse-cluster \
    --install --reuse-values \
    --version="$CHART_VERSION" \
    -n ns-$CLUSTER_NAME \
    --create-namespace \
    --values "$TEMP_VALUES_FILE" \
    --timeout 10m0s; then
      echo "Error: Helm upgrade failed. Please review the output above for details."
      rm -f "$TEMP_VALUES_FILE" # Remove o arquivo temporário em caso de erro
      exit 1
  fi
  
  echo "Helm install completed successfully!"
  
  # 5. Remove o arquivo de valores temporário.
  echo "Cleaning up temporary values file..."
  rm "$TEMP_VALUES_FILE"
  
  # 6. Monitora os pods para verificar o efeito da atualização.
  echo "Monitoring pod status in namespace 'clickhouse-operator-system' (Ctrl+C to exit monitoring):"
  kubectl get pods -n clickhouse-operator-system -w
  
  echo "--- Helm Upgrade Process Complete ---"
```

Este script é usado para aplicar um patch ao secret do Kubernetes e ao StatefulSet do ClickHouse Keeper, o que pode ser essencial para resolver certos problemas de acesso relacionados a image pull secrets ou variáveis de ambiente. <div id="sts_keeper_patch_templateyaml">

Este template YAML é usado pelo script 5&#95;fix&#95;keeper&#95;sts.sh para aplicar um patch ao StatefulSet do ClickHouse Keeper. Ele adiciona imagePullSecrets e injeta a chave de acesso e a chave secreta da AWS como variáveis de ambiente no contêiner do Keeper.

<div id="sts_server_patchsh">
  ###### sts_server_patch.sh
</div>

Este script foi criado para aplicar um patch aos StatefulSets dos pods do servidor ClickHouse. Ele garante que o image pull secret necessário seja aplicado aos StatefulSets do servidor, o que é essencial para baixar imagens de contêiner de registries privados, como o IBM Cloud Container Registry. Ele também inclui tratamento de erros e informa ao usuário que é necessário reiniciar o pod para que as alterações entrem em vigor.

```bash
#!/bin/bash
# Encerra imediatamente se um comando retornar status diferente de zero.
set -euo pipefail

# --- Configuração e Validação ---
# O espaço de nomes e o nome do segredo são passados como argumentos.

if [ "$#" -ne 2 ]; then
  echo "Usage: $0 <NAMESPACE> <IMAGE_PULL_SECRET_NAME>"
  echo "Example: $0 ns-my-cluster all-icr-io"
  exit 1
fi

TARGET_NAMESPACE="$1"
SECRET_NAME="$2"

# --- Lógica do Script ---

echo "--> Verifying secret '$SECRET_NAME' in namespace '$TARGET_NAMESPACE'..."
# 'set -e' fará o script encerrar se o segredo não for encontrado.
kubectl get secret "$SECRET_NAME" -n "$TARGET_NAMESPACE" >/dev/null
echo "    Secret found. Proceeding."

echo "--> Finding StatefulSets containing 'server' in their name..."
# Usa uma consulta jsonpath mais confiável para obter os nomes diretamente.
# O '|| true' garante que o script não falhe se nenhum StatefulSet for encontrado.
STS_LIST=$(kubectl get sts -n "$TARGET_NAMESPACE" --no-headers -o custom-columns=NAME:.metadata.name | grep "server" || true)

if [ -z "$STS_LIST" ]; then
  echo "    No matching 'server' StatefulSets found. Nothing to patch."
  exit 0
fi

echo "--> Found the following StatefulSets to patch:"
echo "$STS_LIST"

PATCH_JSON='{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"'"$SECRET_NAME"'"}]}}}}'

for STS_NAME in $STS_LIST; do
  echo "    - Patching ${STS_NAME}..."
  # Aplica o patch no StatefulSet. Redireciona a saída bem-sucedida para /dev/null para logs mais limpos.
  kubectl patch sts "$STS_NAME" -n "$TARGET_NAMESPACE" -p "$PATCH_JSON" >/dev/null
done

echo
echo "--> Patching process complete."
echo "--> IMPORTANT: Pods must be restarted for the new imagePullSecrets to take effect."
echo "    Example: kubectl delete pod <pod-name> -n ${TARGET_NAMESPACE}"
```

<div id="s3-access-denied-errors">
  ##### Erros de acesso negado ao S3
</div>

Se você encontrar erros de acesso negado relacionados ao S3 nos logs do contêiner (por exemplo, do Keeper), talvez seja necessário injetar as credenciais do S3 nas variáveis de ambiente do pod do Kubernetes. Em vez de usar `kubectl edit`, você pode usar `kubectl patch` com um arquivo YAML.

Exemplo de erro:

```bash
2025.07.10 20:12:36.893641 [ 1 ] {} <Error> Application: Code: 499. DB::Exception: Message: Access Denied, bucket ch-s3-bb1bf91e-0eae-4d02-a842-e75d660d62bc, key ch-s3-00000000-0000-0000-0000-000000000000/keepers/0/log/clickhouse_access_check_eacdcaed-ef86-488c-ae77-22a7ec0db795, object size 4: While checking access for disk s3_keeper_log_disk. (S3_ERROR), Stack trace (when copying this message, always include the lines below): 
```

Crie um arquivo chamado sts&#95;keeper&#95;patch.yaml com o conteúdo a seguir, substituindo YOUR&#95;KEY e YOUR&#95;SECRET pelas suas credenciais da AWS:

```yaml
apiVersion: apps/v1 
kind: StatefulSet 
metadata: 
  name: c-default-xx-01-keeper 
  namespace: ns-default-xx-01 
spec: 
  template: 
    spec: 
      containers: 
        - name: c-default-xx-01-keeper 
          env: 
          - name: AWS_ACCESS_KEY_ID 
            value: YOUR_KEY # Substitua pelo seu AWS Access Key ID 
          - name: AWS_SECRET_ACCESS_KEY 
            value: YOUR_SECRET # Substitua pelo seu AWS Secret Access Key 
```

Em seguida, aplique o patch:

```bash
kubectl patch sts c-default-xx-01-keeper -n ns-default-xx-01 --patch-file sts_keeper_patch.yaml 
```

Após aplicar o patch, acompanhe os pods. Talvez seja necessário excluir o pod problemático para forçar sua recriação com a nova configuração:

```bash
kubectl delete pod c-default-xx-01-keeper-0 -n ns-default-xx-01 
```

Copie o Secret do kubectl para outro espaço de nomes (se necessário)

Se o Secret do kubectl precisar ser copiado para outro espaço de nomes (por exemplo, de default para clickhouse-operator-system), use o comando a seguir. Isso, em princípio, já deve ser tratado pelos scripts.

```bash
kubectl get secret all-icr-io -n default -o yaml | \

  sed 's/  uid: .*//g' | \

```

<div id="run-script-remove_cached_imagessh">
  ##### Execute o script remove_cached_images.sh
</div>

```bash
#!/bin/bash 
set -e 
 
echo "Starting cleanup process on all nodes..." 
echo "-----------------------------------" 
 
kubectl get nodes -o name | while read -r node_ref; do 
  node_name="${node_ref}" 
 
  echo "--> Processing $node_name" 
 
  # Passo 1: Execute o comando de depuração e capture TODA a saída em uma variável. 
  # O '2>&1' garante que tanto a saída padrão quanto os erros sejam capturados. 
  CMD_OUTPUT=$(kubectl debug $node_ref  \ 
    -n default -it --image=busybox --profile=general \ 
    -- sh -c 'chroot /host crictl rmi --all' 2>&1) 
 
  # Passo 2: Exiba apenas as linhas que começam com "Creating" ou "Deleted". 
  # O sinalizador '-E' habilita expressões regulares estendidas para o operador '|' (OU). 
  # O '^' ancora a correspondência ao início da linha. 
  echo "$CMD_OUTPUT" | grep -E '^Creating|^Deleted' 
 
  # Passo 3: Analise a saída completa para encontrar o nome do pod a ser excluído. 
  captured_pod_name=$(echo "$CMD_OUTPUT" | grep "Creating debugging pod" | awk '{print $4}') 
   
  if [ -n "$captured_pod_name" ]; then 
    echo "Cleaning up pod: $captured_pod_name" 
    kubectl delete pod "$captured_pod_name" -n default --wait=false 
  else 
    echo "    Warning: Could not determine pod name for node $node_name." 
  fi 
 
  echo "-----------------------------------" 
done 
 
echo "All nodes have been processed." 
```
