<div id="overview">
  ## Visão geral
</div>

Este guia aborda a implantação do ClickHouse Private no Google Cloud Platform (GCP) usando o Google Kubernetes Engine (GKE). Ele adapta o processo padrão de implantação na AWS para os serviços específicos do GCP, incluindo Artifact Registry, GCS com API compatível com S3 e Workload Identity.

Este guia oferece suporte a implantações **padrão** e **compatíveis com FIPS 140-2**. As etapas e configurações específicas do FIPS estão marcadas com **(FIPS)** ao longo de todo o documento. Defina `ENABLE_FIPS=true` em `00-env.sh` para ativar o modo FIPS.

<div id="prerequisites">
  ## Pré-requisitos
</div>

* Projeto do GCP com faturamento habilitado
* CLI `gcloud` instalada e autenticada
* `kubectl` instalado
* `helm` v3.x instalado
* `skopeo` instalado (para copiar imagens de contêiner)
* Credenciais da AWS com acesso de leitura ao ClickHouse ECR (para copiar imagens)
* **Bastion host** na VPC para acessar o cluster privado
* **Conta de serviço de implantação** com as permissões adequadas (veja abaixo)
* **(FIPS)** Acesso à imagem de contêiner Red Hat UBI8 (baixada via GKE para geração de certificados)

<div id="creating-a-service-account-for-clickhouse-deployment">
  ## Criando uma conta de serviço para a implantação do ClickHouse
</div>

Em ambientes FedRAMP em que a autenticação direta de usuários é restrita, crie uma conta de serviço para impersonação.

<div id="option-1-via-gcp-console">
  ### Opção 1: pelo Console do GCP
</div>

1. Vá para **IAM &amp; Admin** → **Service Accounts**
2. Clique em **+ CREATE SERVICE ACCOUNT**
3. Insira:
   * **Name:** `clickhouse-deployer`
   * **ID:** `clickhouse-deployer`
   * **Description:** `Conta de serviço para implantar a infraestrutura do ClickHouse`
4. Clique em **CREATE AND CONTINUE**
5. Adicione os seguintes papéis:

| Role                                    | Finalidade                                        |
| --------------------------------------- | ------------------------------------------------- |
| `roles/compute.networkAdmin`            | Criar/gerenciar VPC, sub-redes, NAT e roteadores  |
| `roles/container.admin`                 | Criar/gerenciar clusters do GKE e pools de nós    |
| `roles/storage.admin`                   | Criar/gerenciar buckets do GCS                    |
| `roles/iam.serviceAccountAdmin`         | Criar/gerenciar contas de serviço                 |
| `roles/iam.serviceAccountUser`          | Usar contas de serviço com Workload Identity      |
| `roles/iam.workloadIdentityUser`        | Configurar vínculos do Workload Identity          |
| `roles/artifactregistry.admin`          | Criar/gerenciar repositórios do Artifact Registry |
| `roles/resourcemanager.projectIamAdmin` | Gerenciar políticas de IAM no projeto             |

6. Clique em **CONTINUE** → **DONE**

**Conceder a permissão de criador de token:**

1. Clique na conta de serviço `clickhouse-deployer` recém-criada
2. Vá para a aba **PERMISSIONS**
3. Clique em **GRANT ACCESS**
4. Adicione o principal: `<COMPUTE_SERVICE_ACCOUNT>@developer.gserviceaccount.com` (a conta de serviço do seu host bastion)
5. Atribua o papel: `roles/iam.serviceAccountTokenCreator`
6. Clique em **SAVE**

<div id="option-2-via-cli-requires-iam-admin-access">
  ### Opção 2: via CLI (requer acesso de administrador do IAM)
</div>

```bash expandable
PROJECT_ID=your-project-id
SA_EMAIL=clickhouse-deployer@${PROJECT_ID}.iam.gserviceaccount.com
COMPUTE_SA=<COMPUTE_PROJECT_NUMBER>-compute@developer.gserviceaccount.com

# Criar conta de serviço
gcloud iam service-accounts create clickhouse-deployer \
  --display-name="ClickHouse Deployer" \
  --project=${PROJECT_ID}

# Conceder papéis
for role in \
  roles/compute.networkAdmin \
  roles/container.admin \
  roles/storage.admin \
  roles/iam.serviceAccountAdmin \
  roles/iam.serviceAccountUser \
  roles/iam.workloadIdentityUser \
  roles/artifactregistry.admin \
  roles/resourcemanager.projectIamAdmin
do
  gcloud projects add-iam-policy-binding ${PROJECT_ID} \
    --member="serviceAccount:${SA_EMAIL}" \
    --role="${role}"
done

# Permitir que o compute SA o represente
gcloud iam service-accounts add-iam-policy-binding ${SA_EMAIL} \
  --member="serviceAccount:${COMPUTE_SA}" \
  --role="roles/iam.serviceAccountTokenCreator" \
  --project=${PROJECT_ID}
```

<div id="configure-impersonation-on-bastion">
  ### Configure a impersonação no Bastion
</div>

Adicione isto ao seu `00-env.sh` ou execute antes de rodar os scripts:

```bash
# Definir impersonação para a conta de serviço do deployer
gcloud config set auth/impersonate_service_account clickhouse-deployer@${GCP_PROJECT}.iam.gserviceaccount.com

# Verificar se funciona
gcloud compute networks list --project=${GCP_PROJECT}
```

Para remover a impersonação depois:

```bash
gcloud config unset auth/impersonate_service_account
```

<div id="00-environment-variables">
  ## 00. Variáveis de ambiente
</div>

**Arquivo: `00-env.sh`**

```bash expandable
#!/bin/bash
# ============================================
# ClickHouse Private GCP - Configuração do Ambiente
# ============================================
# Atualize estes valores para o seu ambiente

# Projeto e Região do GCP
export GCP_PROJECT=your-project-id
export GCP_REGION=us-central1
export GCP_ZONES="us-central1-a,us-central1-b,us-central1-c"

# Cluster do GKE
export GKE_CLUSTER_NAME=clickhouse-cluster

# Cluster do ClickHouse (pode haver múltiplos por cluster do GKE)
export CLUSTER_NAME=default-xx-01
export NAMESPACE=ns-${CLUSTER_NAME}

# Rede - Use a VPC existente onde o bastion está localizado
export VPC_NAME=clickhouse-vpc
export SUBNET_NAME=gke-subnet
export SUBNET_RANGE=10.1.0.0/24
export POD_RANGE=10.244.0.0/14         # Deve estar no limite /14 (3º octeto divisível por 4)
export SERVICE_RANGE=10.252.0.0/20     # Deve estar no limite /20
export MASTER_IPV4_CIDR=172.16.0.0/28  # Para o control plane do cluster privado
export BASTION_SUBNET_RANGE=10.0.0.0/24  # Sub-rede do bastion (para master-authorized-networks)

# Armazenamento
export BUCKET_NAME=clickhouse-data-${GCP_PROJECT}
export S3_KEY_PREFIX=ch-s3-$(uuidgen | tr '[:upper:]' '[:lower:]')

# Contas de Serviço
export GSA_NAME=clickhouse
export GSA_EMAIL=${GSA_NAME}@${GCP_PROJECT}.iam.gserviceaccount.com
export KSA_NAME=clickhouse

# Registro de Artefatos
export GAR_REPO_NAME=clickhouse
export GAR_HOST=${GCP_REGION}-docker.pkg.dev/${GCP_PROJECT}/${GAR_REPO_NAME}

# Configuração FIPS (defina como true para conformidade com FIPS 140-2)
export ENABLE_FIPS=false

# Versões de Imagem - O modo FIPS utiliza builds compatíveis com FIPS
if [ "$ENABLE_FIPS" = "true" ]; then
  export CLICKHOUSE_SERVER_VERSION=25.8.1.9104-fips
  export CLICKHOUSE_KEEPER_VERSION=26.1.1.1493
else
  export CLICKHOUSE_SERVER_VERSION=25.8.1.9104
  export CLICKHOUSE_KEEPER_VERSION=25.10.1.6624
fi
export CLICKHOUSE_OPERATOR_VERSION=main-1.16067.1
export OPERATOR_HELM_VERSION=1.16067.1
export CLUSTER_HELM_VERSION=1.1.155

# Origem do AWS ECR (para cópia de imagens)
export SOURCE_ECR_REGION=us-east-1
export SOURCE_ECR_REPO=349290138304.dkr.ecr.${SOURCE_ECR_REGION}.amazonaws.com
export AWS_PROFILE=clickhouse-ecr

# Configuração do Pool de Nós
export KEEPER_MACHINE_TYPE=n2-standard-4      # n2-standard-8 recomendado para produção
export SERVER_MACHINE_TYPE=n2-standard-8      # n2-standard-64 recomendado para produção
export DEFAULT_MACHINE_TYPE=n2-standard-4

# Limites de Recursos (ajuste conforme o tamanho das instâncias)
export SERVER_CPU=4                           # Ajuste ao tipo de máquina
export SERVER_MEMORY=16Gi                     # Ajuste ao tipo de máquina
export KEEPER_CPU=2
export KEEPER_MEMORY=8Gi

# Configuração de Cache
export CACHE_BYTES_PER_GI_RAM=11Gi

# Configuração de Certificado FIPS (utilizada apenas quando ENABLE_FIPS=true)
if [ "$ENABLE_FIPS" = "true" ]; then
  export KUBERNETES_DOMAIN=cluster.local
  export CERT_DIR=./certs
  export SELF_SIGNED=true  # Defina como false se estiver usando uma CA existente
fi

# Senha do ClickHouse
# Para produção/FIPS: use o Secret Manager:
#   export CLICKHOUSE_PASSWORD=$(gcloud secrets versions access latest --secret=clickhouse-password --project=${GCP_PROJECT})
export CLICKHOUSE_PASSWORD='change-me-not-for-production'

echo "=========================================="
echo "Environment Variables Set"
echo "=========================================="
echo "GCP Project:     ${GCP_PROJECT}"
echo "GCP Region:      ${GCP_REGION}"
echo "GKE Cluster:     ${GKE_CLUSTER_NAME}"
echo "CH Cluster:      ${CLUSTER_NAME}"
echo "Namespace:       ${NAMESPACE}"
echo "VPC:             ${VPC_NAME}"
echo "Subnet:          ${SUBNET_NAME}"
echo "Bucket:          ${BUCKET_NAME}"
echo "GAR Host:        ${GAR_HOST}"
echo "FIPS Mode:       ${ENABLE_FIPS}"
echo "=========================================="
```

```bash

```

<div id="02-copy-container-images">
  ## 02. Copie as imagens de contêiner
</div>

**Arquivo: `02-copy-images.sh`**

É necessário o [skopeo](https://github.com/containers/skopeo) para preservar todas as arquiteturas.

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "02. Copying ClickHouse Images"
echo "=========================================="

# Verificar se o perfil AWS existe
if ! aws configure list --profile ${AWS_PROFILE} &>/dev/null; then
  echo "ERROR: AWS profile '${AWS_PROFILE}' not found"
  echo "To create the profile, run: aws configure --profile ${AWS_PROFILE}"
  exit 1
fi

# Autenticar no ECR de origem
echo "Authenticating to AWS ECR..."
aws ecr get-login-password --region ${SOURCE_ECR_REGION} --profile ${AWS_PROFILE} | \
  skopeo login --username AWS --password-stdin ${SOURCE_ECR_REPO}
echo "✓ ECR authentication successful"

# Autenticar no GCP Artifact Registry
echo "Authenticating to GCP Artifact Registry..."
gcloud auth configure-docker ${GCP_REGION}-docker.pkg.dev --quiet
echo "✓ GAR authentication successful"

echo ""
echo "Copying images..."

echo "1/5 Copying ClickHouse Server ${CLICKHOUSE_SERVER_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/clickhouse-server:${CLICKHOUSE_SERVER_VERSION} \
  docker://${GAR_HOST}/clickhouse-server:${CLICKHOUSE_SERVER_VERSION}
echo "✓ Server copied"

echo "2/5 Copying ClickHouse Keeper ${CLICKHOUSE_KEEPER_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/clickhouse-keeper:${CLICKHOUSE_KEEPER_VERSION} \
  docker://${GAR_HOST}/clickhouse-keeper:${CLICKHOUSE_KEEPER_VERSION}
echo "✓ Keeper copied"

echo "3/5 Copying ClickHouse Operator ${CLICKHOUSE_OPERATOR_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/clickhouse-operator:${CLICKHOUSE_OPERATOR_VERSION} \
  docker://${GAR_HOST}/clickhouse-operator:${CLICKHOUSE_OPERATOR_VERSION}
echo "✓ Operator copied"

echo "4/5 Copying Operator Helm Chart ${OPERATOR_HELM_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/helm/clickhouse-operator-helm:${OPERATOR_HELM_VERSION} \
  docker://${GAR_HOST}/helm/clickhouse-operator-helm:${OPERATOR_HELM_VERSION}
echo "✓ Operator Helm chart copied"

echo "5/5 Copying Cluster Helm Chart ${CLUSTER_HELM_VERSION}..."
skopeo copy --all \
  docker://${SOURCE_ECR_REPO}/helm/onprem-clickhouse-cluster:${CLUSTER_HELM_VERSION} \
  docker://${GAR_HOST}/helm/onprem-clickhouse-cluster:${CLUSTER_HELM_VERSION}
echo "✓ Cluster Helm chart copied"

echo ""
echo "=========================================="
echo "✅ All images copied successfully!"
echo "=========================================="

# Verificar
echo ""
echo "Verifying images in Artifact Registry..."
gcloud artifacts docker images list ${GAR_HOST} --format="table(package,version)"
```

<div id="03-configure-vpc-and-subnet">
  ## 03. Configurar VPC e sub-rede
</div>

**Arquivo: `03-vpc-subnet.sh`**

Este script considera que você já tenha uma VPC existente com um host bastion. Ele cria ou atualiza a sub-rede do GKE com os intervalos secundários necessários.

**Importante: requisitos de alinhamento de CIDR**

* Blocos `/14`: o terceiro octeto deve ser divisível por 4 (por exemplo, `10.244.0.0`, NÃO `10.245.0.0`)
* Blocos `/20`: o quarto octeto deve ser 0, e o terceiro octeto deve ser múltiplo de 16 (por exemplo, `10.252.0.0`)

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "03. Configuring VPC and GKE Subnet"
echo "=========================================="

# Verificar se a VPC existe
echo "Checking VPC: ${VPC_NAME}..."
if gcloud compute networks describe ${VPC_NAME} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ VPC exists"
else
  echo "   Creating VPC..."
  gcloud compute networks create ${VPC_NAME} \
    --subnet-mode=custom \
    --project=${GCP_PROJECT}
  echo "   ✓ VPC created"
fi

# Verificar se a sub-rede GKE existe
echo ""
echo "Checking GKE subnet: ${SUBNET_NAME}..."
if gcloud compute networks subnets describe ${SUBNET_NAME} --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  # Sub-rede existe - verificar intervalos secundários
  EXISTING_SECONDARY=$(gcloud compute networks subnets describe ${SUBNET_NAME} \
    --region=${GCP_REGION} \
    --project=${GCP_PROJECT} \
    --format="value(secondaryIpRanges.rangeName)" 2>/dev/null | grep -E "^pods$" || true)
  
  if [ -z "$EXISTING_SECONDARY" ]; then
    echo "   ⚠️ Subnet exists but missing secondary ranges"
    echo "   Adding secondary ranges for pods and services..."
    gcloud compute networks subnets update ${SUBNET_NAME} \
      --region=${GCP_REGION} \
      --add-secondary-ranges=pods=${POD_RANGE},services=${SERVICE_RANGE} \
      --project=${GCP_PROJECT}
    echo "   ✓ Secondary ranges added"
  else
    echo "   ✓ Subnet exists with secondary ranges"
  fi
else
  echo "   Creating GKE subnet..."
  gcloud compute networks subnets create ${SUBNET_NAME} \
    --network=${VPC_NAME} \
    --region=${GCP_REGION} \
    --range=${SUBNET_RANGE} \
    --secondary-range=pods=${POD_RANGE},services=${SERVICE_RANGE} \
    --enable-private-ip-google-access \
    --project=${GCP_PROJECT}
  echo "   ✓ Subnet created"
fi

# Habilitar o Private Google Access
echo ""
echo "Ensuring Private Google Access is enabled..."
gcloud compute networks subnets update ${SUBNET_NAME} \
  --region=${GCP_REGION} \
  --enable-private-ip-google-access \
  --project=${GCP_PROJECT} 2>/dev/null || true
echo "   ✓ Private Google Access enabled"

echo ""
echo "=========================================="
echo "✅ VPC/Subnet Configuration Complete!"
echo "=========================================="
echo ""
echo "VPC:          ${VPC_NAME}"
echo "GKE Subnet:   ${SUBNET_NAME} (${SUBNET_RANGE})"
echo "Pods:         ${POD_RANGE}"
echo "Services:     ${SERVICE_RANGE}"
echo "Bastion:      ${BASTION_SUBNET_RANGE}"
```

<div id="04-create-cloud-nat">
  ## 04. Criar Cloud NAT
</div>

**Arquivo: `04-cloud-nat.sh`**

Nós privados do GKE exigem Cloud NAT para acesso de saída à internet (como para baixar imagens, etc.).

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "04. Creating Cloud NAT for Private Nodes"
echo "=========================================="

# Criar Cloud Router
echo "Creating Cloud Router..."
if gcloud compute routers describe clickhouse-router --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ Router already exists"
else
  gcloud compute routers create clickhouse-router \
    --network=${VPC_NAME} \
    --region=${GCP_REGION} \
    --project=${GCP_PROJECT}
  echo "   ✓ Router created"
fi

# Criar Cloud NAT
echo ""
echo "Creating Cloud NAT..."
if gcloud compute routers nats describe clickhouse-nat --router=clickhouse-router --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ NAT already exists"
else
  gcloud compute routers nats create clickhouse-nat \
    --router=clickhouse-router \
    --region=${GCP_REGION} \
    --nat-all-subnet-ip-ranges \
    --auto-allocate-nat-external-ips \
    --enable-logging \
    --log-filter=ERRORS_ONLY \
    --project=${GCP_PROJECT}
  echo "   ✓ NAT created"
fi

echo ""
echo "=========================================="
echo "✅ Cloud NAT Setup Complete!"
echo "=========================================="
echo ""
echo "Router: clickhouse-router"
echo "NAT:    clickhouse-nat"
echo "Region: ${GCP_REGION}"
```

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "06. Creating GCS Bucket"
echo "=========================================="

# Criar bucket
echo "Creating GCS bucket: ${BUCKET_NAME}..."

  echo "   ✓ Bucket already exists"
else
  gcloud storage buckets create gs://${BUCKET_NAME} \
    --project=${GCP_PROJECT} \

    --location=${GCP_REGION} \

echo "   ✓ Uniform access enabled"

# Conceder permissões à service account
echo ""
echo "Granting permissions to service account..."
gcloud storage buckets add-iam-policy-binding gs://${BUCKET_NAME} --member=serviceAccount:${GSA_EMAIL} --role=roles/storage.objectAdmin
gcloud storage buckets add-iam-policy-binding gs://${BUCKET_NAME} --member=serviceAccount:${GSA_EMAIL} --role=roles/storage.legacyBucketReader
echo "   ✓ Permissions granted"

echo ""
echo "=========================================="
echo "✅ GCS Bucket Setup Complete!"
echo "=========================================="
echo ""
echo "Bucket:   ${BUCKET_NAME}"
echo "Region:   ${GCP_REGION}"
echo "Endpoint: https://storage.googleapis.com"
```

  ## 07. Criar cluster do GKE
</div>

**Arquivo: `07-gke-cluster.sh`**

Cria um **cluster do GKE totalmente privado** para atender aos requisitos de conformidade do FedRAMP:

* Os nós de worker têm apenas IPs internos
* O plano de controle tem **apenas um endpoint privado**
* Todo o acesso deve vir de dentro da VPC (via bastion)

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "07. Creating Private GKE Cluster"
echo "=========================================="

echo "Creating cluster: ${GKE_CLUSTER_NAME}..."
if gcloud container clusters describe ${GKE_CLUSTER_NAME} --region=${GCP_REGION} --project=${GCP_PROJECT} &>/dev/null; then
  echo "   ✓ Cluster already exists"
else
  gcloud container clusters create ${GKE_CLUSTER_NAME} \
    --region=${GCP_REGION} \
    --node-locations=${GCP_ZONES} \
    --network=${VPC_NAME} \
    --subnetwork=${SUBNET_NAME} \
    --cluster-secondary-range-name=pods \
    --services-secondary-range-name=services \
    --enable-ip-alias \
    --enable-private-nodes \
    --enable-private-endpoint \
    --master-ipv4-cidr=${MASTER_IPV4_CIDR} \
    --enable-master-authorized-networks \
    --master-authorized-networks=${SUBNET_RANGE},${BASTION_SUBNET_RANGE} \
    --workload-pool=${GCP_PROJECT}.svc.id.goog \
    --num-nodes=1 \
    --machine-type=${DEFAULT_MACHINE_TYPE} \
    --disk-type=pd-standard \
    --disk-size=50 \
    --project=${GCP_PROJECT}
  echo "   ✓ Cluster created"
fi

# Obter credenciais (deve ser executado de dentro da VPC / bastion)
echo ""
echo "Getting cluster credentials..."
gcloud container clusters get-credentials ${GKE_CLUSTER_NAME} \
  --region=${GCP_REGION} \
  --internal-ip \
  --project=${GCP_PROJECT}
echo "   ✓ Credentials configured"

# Verificar acesso
echo ""
echo "Verifying cluster access..."
kubectl get nodes

echo ""
echo "=========================================="
echo "✅ Private GKE Cluster Ready!"
echo "=========================================="
echo ""
echo "Cluster:     ${GKE_CLUSTER_NAME}"
echo "Region:      ${GCP_REGION}"
echo "Master CIDR: ${MASTER_IPV4_CIDR}"
echo ""
echo "Private cluster settings:"
echo "  - Nodes have internal IPs only"
echo "  - Control plane has NO public endpoint"
echo "  - kubectl requires bastion access"
```

**Configurações do cluster privado:**

| Configuração                          | Valor                      | Finalidade                                           |
| ------------------------------------- | -------------------------- | ---------------------------------------------------- |
| `--enable-private-nodes`              | Obrigatório                | Os nós recebem apenas IPs internos                   |
| `--enable-private-endpoint`           | Obrigatório                | O plano de controle não tem IP público (FedRAMP)     |
| `--master-ipv4-cidr`                  | `172.16.0.0/28`            | Faixa de IP do plano de controle                     |
| `--enable-master-authorized-networks` | Obrigatório                | Ativa restrições de rede                             |
| `--master-authorized-networks`        | Sub-redes do GKE + Bastion | CIDRs com permissão para acessar o plano de controle |

<div id="09-local-ssd-daemonset">
  ## 09. Conjunto de Daemon para SSD local
</div>

**Arquivo: `09-local-ssd-daemonset.sh`**

O GKE Container-Optimized OS (COS) tem o sistema de arquivos raiz somente leitura, portanto não podemos criar `/nvme`. Em vez disso, montamos o SSD local em `/mnt/disks/ssd0` e configuramos o ClickHouse para usar esse caminho.

**Observação:** o GKE não permite `--metadata-from-file=startup-script` em pools de nós (chave reservada), portanto é necessário um Conjunto de Daemon para formatar e montar o SSD local.

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "09. Implantando Conjunto de Daemon de SSD Local"
echo "=========================================="

kubectl apply -f - <<'EOF'
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: local-ssd-setup
  namespace: kube-system
spec:
  selector:
    matchLabels:
      app: local-ssd-setup
  template:
    metadata:
      labels:
        app: local-ssd-setup
    spec:
      hostPID: true
      nodeSelector:
        clickhouseGroup: server
      tolerations:
      - key: "clickhouse.com/do-not-schedule"
        operator: "Exists"
        effect: "NoSchedule"
      initContainers:
      - name: setup-ssd
        image: busybox:1.36
        command:
        - /bin/sh
        - -c
        - |
          set -e
          
          # Usa nsenter para executar comandos no host
          nsenter -t 1 -m -- /bin/sh -c '
            # Localizar dispositivo SSD local
            if [ -b /dev/disk/by-id/google-local-nvme-ssd-0 ]; then
              DEV=/dev/disk/by-id/google-local-nvme-ssd-0
            elif [ -b /dev/disk/by-id/google-local-ssd-0 ]; then
              DEV=/dev/disk/by-id/google-local-ssd-0
            else
              echo "No local SSD found"
              exit 0
            fi
            
            mkdir -p /mnt/disks/ssd0
            
            # Formatar se necessário
            if ! blkid $DEV 2>/dev/null | grep -q ext4; then
              echo "Formatting $DEV..."
              mkfs.ext4 -F $DEV
            fi
            
            # Montar se necessário
            if ! mountpoint -q /mnt/disks/ssd0; then
              echo "Mounting $DEV to /mnt/disks/ssd0..."
              mount $DEV /mnt/disks/ssd0
            fi
            chmod 755 /mnt/disks/ssd0
            
            echo "Local SSD ready at /mnt/disks/ssd0"
            df -h /mnt/disks/ssd0
          '
        securityContext:
          privileged: true
      containers:
      - name: pause
        image: gcr.io/google-containers/pause:3.2
EOF

echo ""
echo "Aguardando o Conjunto de Daemon ficar pronto..."
sleep 15
kubectl get ds -n kube-system local-ssd-setup
kubectl get pods -n kube-system -l app=local-ssd-setup
kubectl logs -n kube-system -l app=local-ssd-setup -c setup-ssd

echo ""
echo "=========================================="
echo "✓ Conjunto de Daemon de SSD Local Implantado!"
echo "=========================================="
echo ""
echo "IMPORTANTE: O SSD está montado em /mnt/disks/ssd0"
echo "É necessário configurar o ClickHouse para usar este caminho"
echo "em vez de /nvme/disk (GKE COS possui sistema de arquivos raiz somente leitura)"
```

**Notas importantes:**

* O GKE Container-Optimized OS tem um **sistema de arquivos raiz somente leitura** — não é possível criar `/nvme`
* O SSD local é montado em `/mnt/disks/ssd0`
* Usa a imagem `busybox:1.36` (não requer internet para `apt-get`)
* Usa `nsenter` para executar comandos no sistema de arquivos do host
* O Conjunto de Daemon deve ser implantado **antes** do cluster do ClickHouse para evitar condições de corrida

<div id="14-create-fips-certificates-fips-only">
  ## 14. Criar certificados FIPS (somente FIPS)
</div>

**Arquivo: `14-create-fips-certs.sh`** — Pule esta etapa se `ENABLE_FIPS=false`.

Os certificados compatíveis com FIPS devem ser gerados com algoritmos aprovados pelo FIPS em um ambiente com FIPS habilitado. Este script executa um pod do Kubernetes com Red Hat UBI8 no cluster do GKE com a política criptográfica FIPS habilitada e, em seguida, copia os certificados gerados de volta para o bastion via `kubectl cp`.

**Requisitos:**

* Tamanho mínimo da chave RSA de 3072 bits
* Algoritmo de assinatura SHA-256 ou superior
* Os Subject Alternative Names (SANs) devem incluir os nomes DNS do cluster
* Acesso ao cluster do GKE via `kubectl` (sem necessidade de `docker`)

**Tipos de certificado:**

| Certificado | Arquivos                                 | Finalidade                               | SANs obrigatórios                                                                 |
| ----------- | ---------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| CA          | `ca/ca.crt`, `ca/ca.key`                 | Autoridade certificadora                 | N/A                                                                               |
| Servidor    | `server/server.crt`, `server/server.key` | Conexões com clickhouse-server           | `*.c-${CLUSTER_NAME}-server-headless.ns-${CLUSTER_NAME}.svc.${KUBERNETES_DOMAIN}` |
| Cliente     | `client/client.crt`, `client/client.key` | Conexões originadas do clickhouse-server | Nenhum obrigatório                                                                |
| Keeper      | `keeper/keeper.crt`, `keeper/keeper.key` | Conexões com clickhouse-keeper           | `*.c-${CLUSTER_NAME}-keeper-headless.ns-${CLUSTER_NAME}.svc.${KUBERNETES_DOMAIN}` |

O script executa estas etapas:

1. Cria um ConfigMap com o script de geração dos certificados
2. Executa um pod UBI8 com um initContainer que instala o OpenSSL, define a política criptográfica FIPS via `update-crypto-policies --set FIPS` e gera todos os certificados
3. Copia os certificados de volta para o bastion via `kubectl cp`
4. Remove o pod e o ConfigMap

Consulte `fips/14-create-fips-certs.sh` para ver o script completo.

**Observações importantes:**

* Por padrão, os certificados expiram após 365 dias — ajuste `CERT_VALIDITY` conforme necessário
* O certificado da CA expira após 3650 dias (10 anos)
* Usa chaves RSA de 3072 bits (mínimo compatível com FIPS)
* Mantenha as chaves privadas (arquivos `*.key`) seguras e nunca faça commit delas no controle de versão

<div id="18-bind-workload-identity-to-helm-sa">
  ## 18. Vincule o Workload Identity à SA do Helm
</div>

**Arquivo: `18-bind-helm-workload-identity.sh`**

O Chart do Helm cria sua própria conta de serviço (`ch-${CLUSTER_NAME}-sa`). Você deve vincular o Workload Identity a essa SA para acessar o GCS.

**Importante:** os pods do Keeper e do servidor criados durante a etapa 17 são iniciados *antes* de esse vínculo do Workload Identity existir, então falharão com erros GCS 403 Access Denied. Este script reinicia automaticamente os pods após o vínculo para que eles passem a usar as novas credenciais.

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "18. Vinculando Workload Identity ao Helm SA"
echo "=========================================="

# Aguardar a criação do SA do Helm
echo "Aguardando a criação da service account do Helm..."
timeout=300
elapsed=0
while ! kubectl get serviceaccount ch-${CLUSTER_NAME}-sa -n ${NAMESPACE} &>/dev/null; do
  if [ $elapsed -ge $timeout ]; then
    echo "ERRO: Timeout aguardando a service account do Helm"
    exit 1
  fi
  sleep 5
  elapsed=$((elapsed + 5))
  echo "  Aguardando... (${elapsed}s)"
done
echo "   ✓ Service account do Helm encontrada"

# Anotar o SA criado pelo helm
echo ""
echo "Anotando a service account do Helm..."
kubectl annotate serviceaccount ch-${CLUSTER_NAME}-sa \
  -n ${NAMESPACE} \
  iam.gke.io/gcp-service-account=${GSA_EMAIL} \
  --overwrite
echo "   ✓ Service account anotada"

# Vincular Workload Identity
echo ""
echo "Vinculando Workload Identity..."
gcloud iam service-accounts add-iam-policy-binding ${GSA_EMAIL} \
  --project=${GCP_PROJECT} \
  --role=roles/iam.workloadIdentityUser \
  --member="serviceAccount:${GCP_PROJECT}.svc.id.goog[${NAMESPACE}/ch-${CLUSTER_NAME}-sa]" \
  --quiet
echo "   ✓ Workload Identity vinculada"

echo ""
echo "Verificando anotação..."
kubectl get sa ch-${CLUSTER_NAME}-sa -n ${NAMESPACE} -o yaml | grep -A3 annotations

# Reiniciar os pods para que capturem as novas credenciais de Workload Identity.
# Os pods criados na etapa 17 foram iniciados antes de o vínculo existir, portanto
# não possuem credenciais GCP e falharão com 403 no GCS.
echo ""
echo "Reiniciando os pods de keeper e servidor para capturar o Workload Identity..."
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=keeper --wait=false 2>/dev/null || true
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=server --wait=false 2>/dev/null || true
echo "   ✓ Pods reiniciando"

echo ""
echo "Aguardando os pods de keeper ficarem prontos..."
kubectl wait --for=condition=ready pod \
  -l clickhouseGroup=keeper \
  -n ${NAMESPACE} \
  --timeout=600s
echo "   ✓ Pods de Keeper prontos"

echo ""
echo "Aguardando a criação dos pods de servidor..."
echo "   (O operator cria os servidores após os keepers estarem saudáveis)"
timeout=600
elapsed=0
while ! kubectl get pods -n ${NAMESPACE} -l clickhouseGroup=server -o name 2>/dev/null | grep -q .; do
  if [ $elapsed -ge $timeout ]; then
    echo "ERRO: Timeout aguardando a criação dos pods de servidor"
    echo "  kubectl get pods -n ${NAMESPACE}"
    exit 1
  fi
  sleep 10
  elapsed=$((elapsed + 10))
  echo "  Aguardando os pods de servidor... (${elapsed}s)"
done

echo "Aguardando os pods de servidor ficarem prontos..."
kubectl wait --for=condition=ready pod \
  -l clickhouseGroup=server \
  -n ${NAMESPACE} \
  --timeout=600s
echo "   ✓ Pods de servidor prontos"

echo ""
echo "=========================================="
echo "✅ Workload Identity vinculada ao Helm SA!"
echo "=========================================="
echo ""
kubectl get pods -n ${NAMESPACE}
```

<div id="19-verify-installation">
  ## 19. Verificar a instalação
</div>

**Modo padrão** (sem TLS):

```bash
# Redirecionamento de porta para a porta nativa do ClickHouse
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9000:9000 -n ${NAMESPACE} &

# Conectar com clickhouse-client
clickhouse client --host localhost --port 9000 --password "${CLICKHOUSE_PASSWORD}"
```

**Modo TLS (FIPS)** — Com `openSSL.required=true`, o ClickHouse aceita conexões apenas em portas seguras. Use a porta **9440** (TLS nativo) em vez da 9000:

```bash
# Redirecionamento de porta para a porta nativa segura do ClickHouse
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9440:9440 -n ${NAMESPACE} &

# Conectar com certificados autoassinados
clickhouse client --host localhost --port 9440 \
  --password "${CLICKHOUSE_PASSWORD}" \
  --secure \
  --accept-invalid-certificate
```

A flag `--accept-invalid-certificate` é necessária porque usamos certificados autoassinados. Para ambientes de produção com certificados válidos assinados por uma CA, especifique explicitamente o certificado da CA:

```bash
clickhouse client --host localhost --port 9440 \
  --password "${CLICKHOUSE_PASSWORD}" \
  --secure \
  --config-file <(cat <<'EOF'
<config>
    <openSSL>
        <client>
            <caConfig>./certs/ca/ca.crt</caConfig>
        </client>
    </openSSL>
</config>
EOF
)
```

**Execute uma consulta de teste:**

```sql
SELECT 1;
```

Saída esperada:

```
   ┌─1─┐
1. │ 1 │
   └───┘
1 row in set. Elapsed: 0.001 sec.
```

**Importante (FIPS):** A porta 9000 (nativo sem criptografia) e a 8123 (HTTP sem criptografia) recusarão conexões quando `openSSL.required=true`. Use a porta 9440 (TLS nativo) ou 8443 (HTTPS).

<div id="appendix-fips-specific-considerations">
  ## Apêndice: Considerações específicas do FIPS
</div>

> **Nota:** Esta seção só se aplica quando `ENABLE_FIPS=true` está definido em `00-env.sh`.

<div id="certificate-requirements">
  ### Requisitos para certificados
</div>

A conformidade com o FIPS exige:

* Chaves RSA de, no mínimo, 3072 bits
* Algoritmos de assinatura aprovados pelo FIPS (SHA-256 ou superior)
* Certificados gerados em um ambiente com FIPS habilitado (Red Hat UBI8)
* Validação adequada da cadeia de certificados

<div id="openssl-configuration">
  ### Configuração do OpenSSL
</div>

Tanto o servidor quanto o Keeper devem ter:

* `openSSL.enabled=true` - Habilita o TLS
* `openSSL.required=true` - Exige TLS (rejeita conexões sem TLS)
* `openSSL.selfSigned=true` - Para certificados autoassinados (defina `false` se estiver usando uma CA confiável)

<div id="key-differences-from-standard-gcp-installation">
  ### Principais diferenças em relação à instalação padrão no GCP
</div>

| Configuração                     | Padrão           | FIPS                            |
| -------------------------------- | ---------------- | ------------------------------- |
| Tag da imagem do servidor        | `25.8.1.9104`    | `25.8.1.9104-fips`              |
| Tag da imagem do Keeper          | `25.10.1.6624`   | `26.1.1.1493`                   |
| OpenSSL habilitado               | Não definido     | `true`                          |
| OpenSSL obrigatório              | Não definido     | `true`                          |
| Certificados TLS                 | Não obrigatórios | Obrigatórios (RSA de 3072 bits) |
| Porta de conexão de cliente      | `9000` (nativo)  | `9440` (TLS nativo)             |
| Porta HTTP                       | `8123`           | `8443` (HTTPS)                  |
| Flag `--secure` do cliente       | Não necessária   | Obrigatória                     |
| Flag de certificado autoassinado | N/A              | `--accept-invalid-certificate`  |

</div>

Verifique se os certificados gerados estão em conformidade com o FIPS:

```bash
# Verificar o tamanho da chave
openssl rsa -in ${CERT_DIR}/server/server.key -text -noout | grep "Private-Key"

# Verificar o algoritmo de assinatura
openssl x509 -in ${CERT_DIR}/server/server.crt -text -noout | grep "Signature Algorithm"
```

* Chave privada: 3072 bits
* Algoritmo de assinatura: sha256WithRSAEncryption (ou superior)

<div id="gcs-access-denied-errors-403">
  ### Erros de acesso negado ao GCS (403)
</div>

A causa mais comum é uma **condição de corrida do Workload Identity**: os pods do Kubernetes são iniciados durante a instalação com Helm (Etapa 17) antes que a SA criada pelo Helm (`ch-${CLUSTER_NAME}-sa`) tenha o vínculo do Workload Identity aplicado na Etapa 18. A Etapa 18 agora trata isso automaticamente, reiniciando os pods do Kubernetes após aplicar o vínculo.

Se você ainda vir erros 403:

```bash
# 1. Verificar a anotação do Workload Identity na SA criada pelo Helm
kubectl get sa ch-${CLUSTER_NAME}-sa -n ${NAMESPACE} -o yaml | grep -A5 annotations

# 2. Verificar o vínculo IAM
gcloud iam service-accounts get-iam-policy ${GSA_EMAIL}

# 3. Verificar as permissões do bucket do GCS para a GSA
gcloud storage buckets get-iam-policy gs://${BUCKET_NAME} | grep ${GSA_EMAIL}

# 4. Testar de dentro do pod do Kubernetes (deve retornar o e-mail da GSA)
kubectl exec -it <pod-name> -n ${NAMESPACE} -- curl -s -H "Metadata-Flavor: Google" \
  http://169.254.169.254/computeMetadata/v1/instance/service-accounts/default/email

# 5. Reiniciar os pods do Kubernetes para aplicar as credenciais (se o passo 18 foi executado após a inicialização dos pods do Kubernetes)
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=keeper
kubectl delete pods -n ${NAMESPACE} -l clickhouseGroup=server
```

<div id="connection-refused-on-port-9000-fips">
  ### Conexão recusada na porta 9000 (FIPS)
</div>

Com o TLS FIPS habilitado (`openSSL.required=true`), o ClickHouse não aceita conexões em texto simples. As portas 9000 (nativa) e 8123 (HTTP) recusarão conexões. Use as portas seguras:

| Protocolo | Porta em texto simples | Porta TLS |
| --------- | ---------------------- | --------- |
| Nativo    | 9000                   | **9440**  |
| HTTP      | 8123                   | **8443**  |

```bash
# Errado - conexão recusada
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9000:9000 -n ${NAMESPACE}
clickhouse client --host localhost --port 9000

# Correto
kubectl port-forward svc/c-${CLUSTER_NAME}-server-any 9440:9440 -n ${NAMESPACE}
clickhouse client --host localhost --port 9440 --secure --accept-invalid-certificate
```

<div id="validate-ssd-cache-script">
  ### Script de validação do cache SSD
</div>

`validate-ssd-cache.sh`

```bash expandable
#!/bin/bash
set -e
source ./00-env.sh

echo "=========================================="
echo "17. Validating SSD Cache Configuration"
echo "=========================================="

echo ""
echo "1. Checking DaemonSet status..."
DS_READY=$(kubectl get ds local-ssd-setup -n kube-system -o jsonpath='{.status.numberReady}')
DS_DESIRED=$(kubectl get ds local-ssd-setup -n kube-system -o jsonpath='{.status.desiredNumberScheduled}')

if [ "$DS_READY" = "$DS_DESIRED" ]; then
  echo "✅ DaemonSet ready: $DS_READY/$DS_DESIRED pods"
else
  echo "❌ DaemonSet not ready: $DS_READY/$DS_DESIRED pods"
  exit 1
fi

echo ""
echo "2. Checking ClickHouseCluster SSD configuration..."
SSD_CONFIG=$(kubectl get clickhousecluster c-${CLUSTER_NAME} -n ${NAMESPACE} -o jsonpath='{.spec.ssdCacheConfiguration}')

if echo "$SSD_CONFIG" | jq -e '.hostPathBaseDirectory == "/mnt/disks/ssd0/"' > /dev/null; then
  echo "✅ SSD cache configured in CRD:"
  echo "$SSD_CONFIG" | jq .
else
  echo "❌ SSD cache not properly configured"
  exit 1
fi

echo ""
echo "3. Waiting for server pods to be ready..."
kubectl wait --for=condition=ready pod \
  -l clickhouseGroup=server \
  -n ${NAMESPACE} \
  --timeout=300s

echo ""
echo "4. Checking pod volume mounts..."
SERVER_POD=$(kubectl get pods -n ${NAMESPACE} -l clickhouseGroup=server -o name | head -1)
echo "Checking pod: $SERVER_POD"

CACHE_MOUNT=$(kubectl get $SERVER_POD -n ${NAMESPACE} -o jsonpath='{.spec.containers[0].volumeMounts}' | jq '.[] | select(.name == "ch-cache-volume")')

if [ -n "$CACHE_MOUNT" ]; then
  echo "✅ Cache volume mounted:"
  echo "$CACHE_MOUNT" | jq .
else
  echo "❌ Cache volume not found in pod"
  exit 1
fi

echo ""
echo "5. Checking pod volume definition..."
CACHE_VOL=$(kubectl get $SERVER_POD -n ${NAMESPACE} -o jsonpath='{.spec.volumes}' | jq '.[] | select(.name == "ch-cache-volume")')

if [ -n "$CACHE_VOL" ]; then
  echo "✅ Cache volume defined:"
  echo "$CACHE_VOL" | jq .
else
  echo "❌ Cache volume not found in pod spec"
  exit 1
fi

echo ""
echo "6. Verifying cache is accessible inside container..."
if kubectl exec -n ${NAMESPACE} $SERVER_POD -- df -h /mnt/clickhouse-cache 2>/dev/null; then
  echo "✅ Cache directory accessible and mounted"
else
  echo "❌ Cache directory not accessible"
  exit 1
fi

echo ""
echo "7. Checking cache usage in ClickHouse..."
echo "Connecting to ClickHouse to verify cache configuration..."

# Construir flags de conexão do cliente
CLIENT_FLAGS=(--password="${CLICKHOUSE_PASSWORD}")
if [ "$ENABLE_FIPS" = "true" ]; then
  # No modo FIPS, o OpenSSL é obrigatório — localizar o certificado CA e configurar o TLS
  CA_CERT_PATH=$(kubectl exec -n ${NAMESPACE} $SERVER_POD -- \
    find /etc -name "ca.crt" -type f 2>/dev/null | head -1)
  if [ -z "$CA_CERT_PATH" ]; then
    echo "❌ Could not find CA cert inside container"
    exit 1
  fi
  echo "Using CA cert: $CA_CERT_PATH"

  CLIENT_FLAGS+=(--secure --config-file=/tmp/ch-client-ssl.xml)
  kubectl exec -n ${NAMESPACE} $SERVER_POD -- bash -c "cat > /tmp/ch-client-ssl.xml << EOF
<clickhouse>
  <openSSL>
    <client>
      <caConfig>${CA_CERT_PATH}</caConfig>
    </client>
  </openSSL>
</clickhouse>
EOF"
fi

# Consultar as configurações do cache de sistema de arquivos (o cache SSD é uma camada de cache de sistema de arquivos
# sobre os discos de ObjectStorage, portanto aparece em system.filesystem_cache_settings
# em vez de como um disco independente em system.disks)
CACHE_INFO=$(kubectl exec -n ${NAMESPACE} $SERVER_POD -- clickhouse-client "${CLIENT_FLAGS[@]}" -q "
SELECT
    cache_name,
    path,
    formatReadableSize(max_size) as max_size,
    formatReadableSize(current_size) as current_size,
    current_elements_num,
    is_initialized
FROM system.filesystem_cache_settings
FORMAT Vertical
" 2>/dev/null) || true

if [ -n "$CACHE_INFO" ]; then
  echo "✅ Filesystem cache active in ClickHouse:"
  echo "$CACHE_INFO"
else
  echo "⚠️  Could not query ClickHouse cache info (cluster may still be initializing)"
fi

echo ""
echo "=========================================="
echo "✅ SSD Cache Validation Complete!"
echo "=========================================="
echo ""
echo "Summary:"
echo "  • DaemonSet mounted SSD at: /mnt/disks/ssd0 (on host)"
echo "  • Operator created volume:  ch-cache-volume"
echo "  • Container mount point:    /mnt/clickhouse-cache"
echo "  • Cache size configured:    ${CACHE_BYTES_PER_GI_RAM} per GiB RAM"
echo ""
echo "The SSD cache is fully configured and operational!"
```

<div id="security-best-practices">
  ## Melhores Práticas de Segurança
</div>

1. **Gerenciamento de Certificados** (FIPS)
   * Renove os certificados antes do vencimento (padrão: 365 dias)
   * Armazene as chaves privadas com segurança (use gerenciamento de segredos)
   * Nunca faça commit de certificados no controle de versão
   * Use certificados adequados assinados por uma CA em produção

2. **Segurança de Rede**
   * Use um cluster privado do GKE sem endpoint público
   * Restrinja master-authorized-networks às sub-redes do bastion e do GKE
   * Habilite os logs de fluxo da VPC
   * Use Cloud NAT para acesso de saída controlado

3. **Controle de Acesso**
   * Use Workload Identity em vez de credenciais estáticas
   * Habilite o RBAC do Kubernetes
   * Audite os logs de acesso regularmente
   * Use a impersonação de conta de serviço para implantação

4. **Monitoramento**
   * Monitore as datas de expiração dos certificados (FIPS)
   * Configure alertas para conexões TLS com falha (FIPS)
   * Monitore os padrões de acesso do GCS
   * Habilite o Cloud Audit Logging
