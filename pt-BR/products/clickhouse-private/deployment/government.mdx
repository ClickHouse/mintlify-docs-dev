<div id="prerequisites">
  ### Pré-requisitos
</div>

* O [Guia técnico de configuração do ClickHouse Private na AWS](/pt-BR/products/clickhouse-private/deployment/aws) deve ter sido seguido para configurar os recursos da AWS (não execute a seção de recursos do Kubernetes), com as seguintes considerações para FIPS:
  * O **bucket do S3 criado aqui não pode conter pontos** (`.`) ao usar FIPS, pois os endpoints FIPS do S3 exigem o estilo de host virtual, que não funciona quando o nome do bucket contém pontos.
* Use as seguintes tags de versão:
  * clickhouse-server
    * `<<SERVER_TAG>>-fips`
  * clickhouse-keeper
    * `<<KEEPER_TAG>>`
  * clickhouse-operator
    * `main-<<OPERATOR_TAG>>`
  * helm/clickhouse-operator-helm
    * `<<OPERATOR_TAG>>`
  * helm/onprem-clickhouse-cluster
    * `<<CR_HELM_TAG>>`

<div id="setup-tasks">
  ### Tarefas de configuração
</div>

* [Criar certificados](#creating-certificates-with-openssl) para o seguinte:
  * Autoridade certificadora (se aplicável, por exemplo, se você mesmo for assinar os certificados)
    * Nome: `ca.crt`
  * Certificados:
    * Requisitos para os certificados:
      * Eles devem ser assinados pela autoridade certificadora criada acima ou pela sua autoridade certificadora existente. Se você estiver usando uma autoridade certificadora existente, deverá ter acesso ao certificado para que ele possa ser instalado.
      * Se a conformidade com FIPS for exigida, eles deverão ser criados com algoritmos e ambientes compatíveis com FIPS
      * Você precisará ter acesso à chave pública (certificado) e à chave privada
      * Os nomes alternativos do sujeito (SANs) devem ter as seguintes entradas:
        * `*.c-${CLUSTER_NAME}-{server|keeper}-headless.ns-${CLUSTER_NAME}.svc.cluster.local` - os componentes do cluster usarão esse domínio DNS para se comunicar entre si. Se o seu Kubernetes tiver um nome de domínio diferente (`.cluster.local`), substitua-o pelo nome de domínio do seu Kubernetes
          * `${CLUSTER_NAME}` é o nome do cluster que você está criando
          * `{server|keeper}` indica que `server` ou `keeper` deve ser usado aqui, dependendo de o certificado estar sendo instalado em `clickhouse-server` ou `clickhouse-keeper`, respectivamente
          * Exemplo para o nome de cluster `default-xx-01`:
            * Server: `*.c-default-xx-01-server-headless.ns-default-xx-01.svc.cluster.local`
            * Keeper: `*.c-default-xx-01-keeper-headless.ns-default-xx-01.svc.cluster.local`
    * Certificados a serem criados:
      * Um para conexões com clickhouse-server
        * Nome da chave privada: `server.key`
        * Nome da chave pública: `server.crt`
      * Um para conexões originadas do clickhouse-server (por exemplo, para clickhouse-keeper e outras fontes HTTPS, como dictionaries)
        * Nome da chave privada: `client.key`
        * Nome da chave pública: `client.crt`
      * Um para conexões com clickhouse-keeper
        * Nome da chave privada: `keeper.key`
        * Nome da chave pública: `keeper.crt`

<div id="creating-certificates-with-openssl">
  #### Criando certificados com OpenSSL
</div>

A seguir, mostramos como criar certificados autoassinados usando o OpenSSL. Certifique-se de que esse método de criação e assinatura de certificados esteja em conformidade com suas políticas de segurança antes de usá-lo em um ambiente de produção. Antes de prosseguir, você deve [escolher um nome para o cluster](/pt-BR/products/clickhouse-private/deployment/aws#naming-your-clickhouse-cluster), e ele deverá ser usado posteriormente ao [criar seu cluster](#clickhousecluster-cr). **Um conjunto exclusivo de certificados (excluindo o certificado da CA) deve ser criado para cada cluster do ClickHouse que estiver sendo provisionado**.

Isso pressupõe que você queira um certificado compatível com FIPS e que tenha o Docker instalado com acesso ao repositório de imagens Docker da Red Hat. Se tudo ocorrer corretamente, isso gerará uma autoridade certificadora que poderá ser usada para assinatura e verificação de certificados, além de três conjuntos de certificados (um para o clickhouse-keeper, um para o clickhouse-server e um para o cliente do clickhouse-server). Você precisará manter os arquivos `*.crt` (certificado/chave pública) e os arquivos `*.key` (chave privada) de cada diretório (`ca/`, `server/`, `keeper/` e `client/`).

Se você tiver sua própria autoridade certificadora para fazer a assinatura, poderá excluir do script a geração do certificado da CA e montar seu próprio certificado da CA na imagem Docker para usá-lo na assinatura. Use uma cópia desse certificado da CA nas etapas posteriores deste guia de configuração quando houver referência a `ca.crt` (por exemplo, ao criar os secrets do Kubernetes).

Observe que os certificados gerados abaixo expiram após 365 dias. Ajuste isso de acordo com seus requisitos de segurança e crie um lembrete para regenerá-los antes que expirem.

```
# atualize as variáveis abaixo conforme necessário:

CLUSTER_NAME=default-xx-01
KUBERNETES_DOMAIN=cluster.local
COUNTRY=US
STATE=YourState
CITY=YourCity
ORG=YourOrganization
ORG_UNIT=YourOrganizationalUnit
CN=YourRootCA

docker run -it --rm \
  -v $(pwd):/certs \
  registry.access.redhat.com/ubi8/ubi \
  /bin/bash -c "
    set -e

    # Instalar pacotes necessários
    dnf -y install openssl crypto-policies-scripts

    # Habilitar o modo FIPS
    fips-mode-setup --enable

    # Criar estrutura de diretórios no volume montado
    mkdir -p /certs/{ca,server,keeper,client}

    # Gerar certificado de CA
    cd /certs/ca
    openssl genrsa -out ca.key 3072

    cat > ca.cnf << EOF
[ req ]
distinguished_name = req_distinguished_name
req_extensions     = v3_ca
prompt             = no

[ req_distinguished_name ]
C  = ${COUNTRY}
ST = ${STATE}
L  = ${CITY}
O  = ${ORG}
OU = ${ORG_UNIT}
CN = ${CN}

[ v3_ca ]
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid:always,issuer:always
basicConstraints = critical, CA:true
keyUsage = critical, digitalSignature, cRLSign, keyCertSign
EOF

    openssl req -new -x509 -days 3650 -key ca.key -out ca.crt -config ca.cnf

    # Gerar certificado do servidor
    cd /certs/server

    cat > server.cnf << EOF
[ req ]
distinguished_name = req_distinguished_name
req_extensions     = v3_req
prompt             = no

[ req_distinguished_name ]
C  = ${COUNTRY}
ST = ${STATE}
L  = ${CITY}
O  = ${ORG}
OU = ${ORG_UNIT}
CN = clickhouse-server

[ v3_req ]
subjectKeyIdentifier = hash
basicConstraints = CA:FALSE
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth, clientAuth
subjectAltName = @alt_names

[ alt_names ]
DNS.1 = *.c-${CLUSTER_NAME}-server-headless.ns-${CLUSTER_NAME}.svc.${KUBERNETES_DOMAIN}
EOF

    openssl genrsa -out server.key 3072
    openssl req -new -key server.key -out server.csr -config server.cnf
    openssl x509 -req -days 365 -in server.csr -CA /certs/ca/ca.crt -CAkey /certs/ca/ca.key \
      -CAcreateserial -out server.crt -extensions v3_req -extfile server.cnf

    # Gerar certificado do Keeper
    cd /certs/keeper

    cat > keeper.cnf << EOF
[ req ]
distinguished_name = req_distinguished_name
req_extensions     = v3_req
prompt             = no

[ req_distinguished_name ]
C  = ${COUNTRY}
ST = ${STATE}
L  = ${CITY}
O  = ${ORG}
OU = ${ORG_UNIT}
CN = clickhouse-keeper

[ v3_req ]
subjectKeyIdentifier = hash
basicConstraints = CA:FALSE
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth, clientAuth
subjectAltName = @alt_names

[ alt_names ]
DNS.1 = *.c-${CLUSTER_NAME}-keeper-headless.ns-${CLUSTER_NAME}.svc.${KUBERNETES_DOMAIN}
EOF

    openssl genrsa -out keeper.key 3072
    openssl req -new -key keeper.key -out keeper.csr -config keeper.cnf
    openssl x509 -req -days 365 -in keeper.csr -CA /certs/ca/ca.crt -CAkey /certs/ca/ca.key \
      -CAcreateserial -out keeper.crt -extensions v3_req -extfile keeper.cnf

    # Gerar certificado do cliente
    cd /certs/client

    cat > client.cnf << EOF
[ req ]
distinguished_name = req_distinguished_name
req_extensions     = v3_req
prompt             = no

[ req_distinguished_name ]
C  = ${COUNTRY}
ST = ${STATE}
L  = ${CITY}
O  = ${ORG}
OU = ${ORG_UNIT}
CN = clickhouse-client

[ v3_req ]
subjectKeyIdentifier = hash
basicConstraints = CA:FALSE
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = clientAuth
EOF

    openssl genrsa -out client.key 3072
    openssl req -new -key client.key -out client.csr -config client.cnf
    openssl x509 -req -days 365 -in client.csr -CA /certs/ca/ca.crt -CAkey /certs/ca/ca.key \
      -CAcreateserial -out client.crt -extensions v3_req -extfile client.cnf

    # Corrigir permissões
    chmod -R 755 /certs

    # Verificar conformidade com FIPS
    echo 'Verifying FIPS compliance of generated certificates:'
    openssl version
    openssl rsa -in /certs/server/server.key -text -noout | grep 'Private-Key'
    openssl x509 -in /certs/server/server.crt -text -noout | grep 'Signature Algorithm'

    # Exibir mensagem de sucesso
    echo 'FIPS-compliant certificates have been generated successfully!'
  "
```

<div id="install-operator-via-helm">
  #### Instale o operador com Helm
</div>

Atualize a versão, o host do ECR e as zonas de disponibilidade (conforme definido pela VPC criada), conforme necessário.

```
# atualize ECR_HOST conforme necessário
ECR_HOST=0000000000.dkr-ecr-fips.us-west-2.on.aws

# deve usar a versão do chart do Helm do operador, não do próprio operador (ex: <<OPERATOR_TAG>>, não main-<<OPERATOR_TAG>>)
OPERATOR_VERSION=<<OPERATOR_TAG>>

# defina as AZs conforme determinado pelas sub-redes da VPC
AZ_LIST='["us-west-2a","us-west-2b","us-west-2c"]'

helm install clickhouse-operator \
   oci://$ECR_HOST/helm/clickhouse-operator-helm \
   --version=$OPERATOR_VERSION \
   --create-namespace \
   -n clickhouse-operator-system \
   --set-json="image.repository=\"$ECR_HOST/clickhouse-operator\"" \
   --set-json='cilium.enabled=false' \
   --set-json='idleScalerEnabled=false' \
   --set-json='webhooks.enabled=false' \
   --set-json='operator.debug=true' \
   --set-json='operator.metricsScraper.enabled=false' \
   --set-json="operator.availabilityZones=$AZ_LIST" \
   --set-json='operator.featureFlags.backupOnASeparatePod=true' \
   --set-json='operator.featureFlags.serverCMEKEnabled=true'
```

<div id="create-kubernetes-certificate-secrets">
  #### Criar secrets de certificados do Kubernetes
</div>

Os secrets devem ser instalados no mesmo espaço de nomes do Kubernetes em que o cluster do ClickHouse será executado. Se o nome do seu cluster for `default-xx-01`, então o espaço de nomes em que ele será executado será `ns-default-xx-01`. Certifique-se de que esse espaço de nomes exista e atualize as variáveis `CERT_DIR` e `CLUSTER_NAME` abaixo antes de executar os comandos.

Os secrets devem ter os nomes gerados abaixo, com os nomes de chave conforme especificado. **Não altere os nomes dos secrets nem os nomes das chaves**.

```
CERT_DIR=.
CLUSTER_NAME=default-xx-01

# servidor
kubectl create secret generic -n ns-${CLUSTER_NAME} ${CLUSTER_NAME}-server-cert-secret \
  --from-file=ca.crt="$CERT_DIR/ca/ca.crt" \
  --from-file=server.crt="$CERT_DIR/server/server.crt" \
  --from-file=server.key="$CERT_DIR/server/server.key" \
  --from-file=client.crt="$CERT_DIR/client/client.crt" \
  --from-file=client.key="$CERT_DIR/client/client.key"

# keeper
kubectl create secret generic -n ns-${CLUSTER_NAME} ${CLUSTER_NAME}-keeper-cert-secret \
  --from-file=ca.crt="$CERT_DIR/ca/ca.crt" \
  --from-file=keeper.crt="$CERT_DIR/keeper/keeper.crt" \
  --from-file=keeper.key="$CERT_DIR/keeper/keeper.key"
```

<div id="clickhousecluster-cr">
  #### Clickhousecluster CR
</div>

Certifique-se de usar a versão FIPS correta dos endpoints abaixo para ECR e S3, que podem ser encontrados [aqui](https://aws.amazon.com/compliance/fips/).

```
# esta será a senha do usuário `default`
PASSWORD='My super secret p@$$w0rd'
HASHED_PASSWORD=`echo -n $PASSWORD | shasum -a 256 | awk '{printf $1}' | base64`

# atualize os valores abaixo conforme necessário,
# o host do ecr deve ser o da sua conta
# o bucket do S3 deve ser o criado anteriormente
CLUSTER_NAME=default-xx-01
ECR_HOST=0000000000.dkr-ecr-fips.us-west-2.on.aws
SA_IAM_ROLE_ARN=arn:aws:iam::0000000000:role/CH-S3-${CLUSTER_NAME}-uw2-00-Role

S3_BUCKET_REGION=us-gov-west-1
S3_BUCKET_URL=https://my-clickhouse-data.us-gov-west-1.amazonaws.com
S3_BUCKET_NAME=my-clickhouse-data

# o prefixo de chave do s3 pode usar qualquer valor UUID, mas deve ser único para todos os clusters que armazenam dados no bucket especificado acima
S3_KEY_PREFIX=ch-s3-$(uuidgen | tr '[:upper:]' '[:lower:]')

# estes devem corresponder ao valor do label clickhouseGroup adicionado ao grupo de nós
SERVER_NG_GROUP=server-arm64
KEEPER_NG_GROUP=keeper-arm64

# estes valores devem ser ajustados conforme os tamanhos de instância selecionados
# certifique-se de considerar os requisitos do daemon set ao definir os valores de CPU e MEMORY
SERVER_CPU=64
SERVER_MEMORY=256Gi
KEEPER_CPU=4
KEEPER_MEMORY=16Gi

# atualize conforme seus certificados sejam ou não autoassinados:
SERVER_SELF_SIGNED=true
KEEPER_SELF_SIGNED=true

CHART_VERSION=<<CR_HELM_TAG>>

# Como regra geral, defina o tamanho do cache para 80-90% do tamanho disponível do disco de cache SSD.
# Por exemplo, para o tipo m6id.2xlarge com 1x474 NVMe, o valor deve ser 379Gi (~80%)
CACHE_DISK_SIZE_GI=379Gi

helm install $CLUSTER_NAME \    oci://$ECR_HOST/helm/onprem-clickhouse-cluster \
    --version=$CHART_VERSION \
    -n ns-$CLUSTER_NAME \
    --create-namespace \
    --set-json="account.hashedPassword=\"$HASHED_PASSWORD\"" \
    --set-json="server.image.repository=\"$ECR_HOST/clickhouse-server\"" \
    --set-json="server.storage.s3.endpoint=\"$S3_BUCKET_URL\"" \
    --set-json="server.storage.s3.region=\"$S3_BUCKET_REGION\"" \
    --set-json="server.storage.s3.bucketName=\"$S3_BUCKET_NAME\"" \
    --set-json="server.storage.s3.keyPrefix=\"$S3_KEY_PREFIX\"" \
    --set-json='server.arm64=true \
    --set-json="server.image.tag=\"<<SERVER_TAG>>-fips\"" \
    --set-json="server.podPolicy.nodeSelector.clickhouseGroup=\"$SERVER_NG_GROUP\"" \
    --set-json="server.openSSL.enabled=true" \
    --set-json="server.openSSL.required=true" \
    --set-json="server.openSSL.selfSigned=$SERVER_SELF_SIGNED" \
    --set-json="keeper.image.repository=\"$ECR_HOST/clickhouse-keeper\"" \
    --set-json='keeper.arm64=true \
    --set-json="keeper.image.tag=\"<<KEEPER_TAG>>\"" \
    --set-json="keeper.podPolicy.nodeSelector.clickhouseGroup=\"$KEEPER_NG_GROUP\"" \
    --set-json="keeper.openSSL.enabled=true" \
    --set-json="keeper.openSSL.required=true" \
    --set-json="keeper.openSSL.selfSigned=$KEEPER_SELF_SIGNED" \
    --set-json="serviceAccount.annotations={\"eks.amazonaws.com/role-arn\":\"$SA_IAM_ROLE_ARN\"}" \
    --set-json='server.tolerations=[{"effect":"NoSchedule","key":"clickhouse.com/do-not-schedule","operator":"Exists"}]' \
    --set-json='keeper.tolerations=[{"effect":"NoSchedule","key":"clickhouse.com/do-not-schedule","operator":"Exists"}]' \
    --set-json="server.ssdCacheConfiguration.cacheDiskSize=\"$CACHE_DISK_SIZE_GI\"" \
    --set-json="server.podPolicy.resources.limits.cpu=\"$SERVER_CPU\"" \
    --set-json="server.podPolicy.resources.limits.memory=\"$SERVER_MEMORY\"" \
    --set-json="server.podPolicy.resources.requests.cpu=\"$SERVER_CPU\"" \
    --set-json="server.podPolicy.resources.requests.memory=\"$SERVER_MEMORY\"" \
    --set-json="keeper.podPolicy.resources.limits.cpu=\"$KEEPER_CPU\"" \
    --set-json="keeper.podPolicy.resources.limits.memory=\"$KEEPER_MEMORY\"" \
    --set-json="keeper.podPolicy.resources.requests.cpu=\"$KEEPER_CPU\"" \
    --set-json="keeper.podPolicy.resources.requests.memory=\"$KEEPER_MEMORY\""
```

<div id="port-forward-the-clickhouse-service-to-your-local-machine">
  #### Faça o redirecionamento de porta do serviço do ClickHouse para sua máquina local
</div>

Para redirecionar o tráfego da sua máquina local para o serviço c-default-xx-01-server-any, execute:

```
kubectl port-forward svc/c-default-xx-01-server-any 9440:9440 -n ns-default-xx-01
```

Isso encaminhará a porta `9440` do serviço para a porta `9440` na sua máquina local. Agora você pode acessar a interface HTTP do ClickHouse em `https://localhost:9440`.

<div id="access-clickhouse-and-run-query">
  #### Acesse o ClickHouse e execute uma consulta
</div>

Depois de encaminhar a porta, você pode se conectar ao ClickHouse localmente usando uma ferramenta como o `clickhouse-client` com o arquivo de configuração a seguir. Não se esqueça de atualizar o caminho para o arquivo `ca.crt`.

```
# client-config.xml
<config>
    <openSSL>
        <client>
            <caConfig>/path/to/certs/ca.crt</caConfig>
        </client>
    </openSSL>
</config>

clickhouse client --host localhost --port 9440 --password $PASSWORD --secure --config=client-config.xml
```

e execute uma consulta simples:

```
clickhouse-cloud :) select 1;
```

Você deverá ver uma saída como esta:

```
SELECT 1
Query id: 825591bf-a8e5-4995-ac9f-afb864854ba2
   ┌─1─┐
1. │ 1  │
   └───┘
1 row in set. Elapsed: 0.001 sec.
```
