## Non-admin users <a id="non-admin-users"></a>

Users should have the privileges necessary, and not all be admin users. The rest of this document provides example scenarios and the roles required.

### Preparation <a id="preparation"></a>

Create these tables and users to be used in the examples.

#### Creating roles <a id="creating-roles"></a>

With this set of examples:

- roles for different privileges, such as columns and rows will be created
- privileges will be granted to the roles
- users will be assigned to each role

Roles are used to define groups of users for certain privileges instead of managing each user separately.

<Steps>
<Step>
##### Create a role to restrict users of this role to only see `column1` in database `db1` and `table1`: <a id="create-column-role"></a>

    ```sql
    CREATE ROLE column1_users;
    ```
</Step>
<Step>
##### Set privileges to allow view on `column1` <a id="set-column-privileges"></a>

    ```sql
    GRANT SELECT(id, column1) ON db1.table1 TO column1_users;
    ```
</Step>
<Step>
##### Add the `column_user` user to the `column1_users` role <a id="add-column-user-to-role"></a>

    ```sql
    GRANT column1_users TO column_user;
    ```
</Step>
<Step>
##### Create a role to restrict users of this role to only see selected rows, in this case, only rows containing `A` in `column1` <a id="create-row-role"></a>

    ```sql
    CREATE ROLE A_rows_users;
    ```
</Step>
<Step>
##### Add the `row_user` to the `A_rows_users` role <a id="add-row-user-to-role"></a>

    ```sql
    GRANT A_rows_users TO row_user;
    ```
</Step>
<Step>
##### Create a policy to allow view on only where `column1` has the values of `A` <a id="create-row-policy"></a>

    ```sql
    CREATE ROW POLICY A_row_filter ON db1.table1 FOR SELECT USING column1 = 'A' TO A_rows_users;
    ```
</Step>
<Step>
##### Set privileges to the database and table <a id="set-db-table-privileges"></a>

    ```sql
    GRANT SELECT(id, column1, column2) ON db1.table1 TO A_rows_users;
    ```
</Step>
<Step>
##### Grant explicit permissions for other roles to still have access to all rows <a id="grant-other-roles-access"></a>

    ```sql
    CREATE ROW POLICY allow_other_users_filter 
    ON db1.table1 FOR SELECT USING 1 TO clickhouse_admin, column1_users;
    ```

<Note>
    When attaching a policy to a table, the system will apply that policy, and only those users and roles defined will be able to do operations on the table, all others will be denied any operations. In order to not have the restrictive row policy applied to other users, another policy must be defined to allow other users and roles to have regular or other types of access.
</Note>
</Step>
</Steps>

## Modifying users and roles <a id="modifying-users-and-roles"></a>

Users can be assigned multiple roles for a combination of privileges needed. When using multiple roles, the system will combine the roles to determine privileges, the net effect will be that the role permissions will be cumulative.

For example, if one `role1` allows for only select on `column1` and `role2` allows for select on `column1` and `column2` then the user will have access to both columns.

<Steps>
<Step>
##### Using the admin account, create new user to restrict by both row and column with default roles <a id="create-restricted-user"></a>

   ```sql
   CREATE USER row_and_column_user IDENTIFIED BY 'password' DEFAULT ROLE A_rows_users;
   ```
</Step>
<Step>
##### Remove prior privileges for `A_rows_users` role <a id="remove-prior-privileges"></a>

   ```sql
   REVOKE SELECT(id, column1, column2) ON db1.table1 FROM A_rows_users;
   ```
</Step>
<Step>
##### Allow `A_row_users` role to only select from `column1` <a id="allow-column1-select"></a>

   ```sql
   GRANT SELECT(id, column1) ON db1.table1 TO A_rows_users;
   ```
</Step>
<Step>
##### Log into the ClickHouse client using `row_and_column_user` <a id="login-restricted-user"></a>

   ```bash
   clickhouse-client --user row_and_column_user --password password;
   ```
</Step>
<Step>
##### Test with all columns: <a id="test-all-columns-restricted"></a>

   ```sql
   SELECT *
   FROM db1.table1
   ```

   ```response
   Query id: 8cdf0ff5-e711-4cbe-bd28-3c02e52e8bc4

   0 rows in set. Elapsed: 0.005 sec.

   Received exception from server (version 22.3.2):
   Code: 497. DB::Exception: Received from localhost:9000. 
   DB::Exception: row_and_column_user: Not enough privileges. 
   To execute this query it's necessary to have grant 
   SELECT(id, column1, column2) ON db1.table1. (ACCESS_DENIED)
   ```
</Step>
<Step>
##### Test with limited allowed columns: <a id="test-limited-columns"></a>

   ```sql
   SELECT
       id,
       column1
   FROM db1.table1
   ```

   ```response
   Query id: 5e30b490-507a-49e9-9778-8159799a6ed0

   ┌─id─┬─column1─┐
   │  1 │ A       │
   │  2 │ A       │
   └────┴─────────┘
   ```
</Step>
</Steps>

## Troubleshooting <a id="troubleshooting"></a>

There are occasions when privileges intersect or combine to produce unexpected results, the following commands can be used to narrow the issue using an admin account

### Listing the grants and roles for a user <a id="listing-the-grants-and-roles-for-a-user"></a>

```sql
SHOW GRANTS FOR row_and_column_user
```

```response
Query id: 6a73a3fe-2659-4aca-95c5-d012c138097b

┌─GRANTS FOR row_and_column_user───────────────────────────┐
│ GRANT A_rows_users, column1_users TO row_and_column_user │
└──────────────────────────────────────────────────────────┘
```

### List roles in ClickHouse <a id="list-roles-in-clickhouse"></a>

```sql
SHOW ROLES
```

```response
Query id: 1e21440a-18d9-4e75-8f0e-66ec9b36470a

┌─name────────────┐
│ A_rows_users    │
│ column1_users   │
└─────────────────┘
```

### Display the policies <a id="display-the-policies"></a>

```sql
SHOW ROW POLICIES
```

```response
Query id: f2c636e9-f955-4d79-8e80-af40ea227ebc

┌─name───────────────────────────────────┐
│ A_row_filter ON db1.table1             │
│ allow_other_users_filter ON db1.table1 │
└────────────────────────────────────────┘
```

### View how a policy was defined and current privileges <a id="view-how-a-policy-was-defined-and-current-privileges"></a>

```sql
SHOW CREATE ROW POLICY A_row_filter ON db1.table1
```

```response

┌─CREATE ROW POLICY A_row_filter ON db1.table1────────────────────────────────────────────────┐
│ CREATE ROW POLICY A_row_filter ON db1.table1 FOR SELECT USING column1 = 'A' TO A_rows_users │

```

## Example commands to manage roles, policies, and users <a id="example-commands-to-manage-roles-policies-and-users"></a>

The following commands can be used to:

- delete privileges
- delete policies
- unassign users from roles
- delete users and roles
  <br />

<Tip>
Run these commands as an admin user or the `default` user
</Tip>

### Remove privilege from a role <a id="remove-privilege-from-a-role"></a>

```sql
REVOKE SELECT(column1, id) ON db1.table1 FROM A_rows_users;
```

### Delete a policy <a id="delete-a-policy"></a>

```sql
DROP ROW POLICY A_row_filter ON db1.table1;
```

### Unassign a user from a role <a id="unassign-a-user-from-a-role"></a>

```sql
REVOKE A_rows_users FROM row_user;
```

### Delete a role <a id="delete-a-role"></a>

```sql
DROP ROLE A_rows_users;
```

### Delete a user <a id="delete-a-user"></a>

```sql
DROP USER row_user;
```
