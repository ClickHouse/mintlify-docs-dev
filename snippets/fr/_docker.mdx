<div id="install-clickhouse-using-docker">
  # Installer ClickHouse avec Docker
</div>

Le guide disponible sur [Docker Hub](https://hub.docker.com/r/clickhouse/clickhouse-server/)
est repris ci-dessous à titre pratique. Les images Docker disponibles utilisent
les paquets deb officiels de ClickHouse.

Commande `docker pull` :

```bash
docker pull clickhouse/clickhouse-server
```

<div id="versions">
  ## Versions
</div>

* Le tag `latest` pointe vers la dernière version de la branche stable la plus récente.
* Les tags de branche comme `22.2` pointent vers la dernière version de la branche correspondante.
* Les tags de version complète comme `22.2.3` et `22.2.3.5` pointent vers la version correspondante.
* Le tag `head` est construit à partir du dernier commit de la branche par défaut.
* Chaque tag peut avoir le suffixe `-alpine` pour indiquer qu&#39;il est construit sur `alpine`.

<div id="compatibility">
  ### Compatibilité
</div>

* L’image amd64 nécessite la prise en charge des [instructions SSE3](https://en.wikipedia.org/wiki/SSE3).
  La quasi-totalité des CPU x86 produits après 2005 prennent en charge SSE3.
* L’image arm64 nécessite la prise en charge de l’[architecture ARMv8.2-A](https://en.wikipedia.org/wiki/AArch64#ARMv8.2-A) et,
  en plus, du registre Load-Acquire RCpc. Ce registre est facultatif dans ARMv8.2-A et obligatoire dans
  [ARMv8.3-A](https://en.wikipedia.org/wiki/AArch64#ARMv8.3-A). Il est pris en charge sur les instances Graviton &gt;=2, Azure et GCP.
  Exemples d’appareils non pris en charge : Raspberry Pi 4 (ARMv8.0-A) et Jetson AGX Xavier/Orin (ARMv8.2-A).
* Depuis ClickHouse 24.11, les images Ubuntu utilisent `ubuntu:22.04` comme image de base. Cela nécessite docker version &gt;= `20.10.10`,
  incluant ce [patch](https://github.com/moby/moby/commit/977283509f75303bc6612665a04abf76ff1d2468). Comme solution de contournement, vous pouvez
  utiliser `docker run --security-opt seccomp=unconfined` à la place ; cela a toutefois des implications en matière de sécurité.

<div id="how-to-use-image">
  ## Comment utiliser cette image
</div>

<div id="start-server-instance">
  ### Démarrer une instance de serveur
</div>

```bash
docker run -d --name some-clickhouse-server --ulimit nofile=262144:262144 clickhouse/clickhouse-server
```

Par défaut, ClickHouse sera accessible uniquement via le réseau Docker. Voir la section sur la mise en réseau ci-dessous.

Par défaut, l’instance de serveur démarrée ci-dessus s’exécutera en tant qu’utilisateur `default`, sans mot de passe.

<div id="connect-to-it-from-native-client">
  ### S’y connecter avec un client natif
</div>

```bash
docker run -it --rm --network=container:some-clickhouse-server --entrypoint clickhouse-client clickhouse/clickhouse-server
# OR
docker exec -it some-clickhouse-server clickhouse-client
```

Consultez [ClickHouse client](/fr/concepts/features/interfaces/cli) pour plus d’informations sur le client ClickHouse.

<div id="connect-to-it-using-curl">
  ### Se connecter avec curl
</div>

```bash
echo "SELECT 'Hello, ClickHouse!'" | docker run -i --rm --network=container:some-clickhouse-server buildpack-deps:curl curl 'http://localhost:8123/?query=' -s --data-binary @-
```

Voir [ClickHouse HTTP Interface](/fr/concepts/features/interfaces/http) pour plus d’informations sur l’interface HTTP.

<div id="stopping-removing-container">
  ### Arrêt / suppression du conteneur
</div>

```bash
docker stop some-clickhouse-server
docker rm some-clickhouse-server
```

<div id="networking">
  ### Réseau
</div>

<Note>
  l’utilisateur prédéfini `default` n’a pas d’accès au réseau tant qu’aucun mot de passe n’est défini,
  voir &quot;Comment créer la base de données et l’utilisateur par défaut au démarrage&quot; et &quot;Gestion de l’utilisateur `default`&quot; ci-dessous
</Note>

Vous pouvez exposer votre instance ClickHouse exécutée dans Docker en [associant un port spécifique](https://docs.docker.com/config/containers/container-networking/)
depuis l’intérieur du conteneur à l’aide des ports de l’hôte :

```bash
docker run -d -p 18123:8123 -p19000:9000 -e CLICKHOUSE_PASSWORD=changeme --name some-clickhouse-server --ulimit nofile=262144:262144 clickhouse/clickhouse-server
echo 'SELECT version()' | curl 'http://localhost:18123/?password=changeme' --data-binary @-
```

Ou en autorisant le conteneur à utiliser [directement les ports de l’hôte](https://docs.docker.com/network/host/) avec `--network=host`
(permet également d’obtenir de meilleures performances réseau) :

```bash
docker run -d --network=host --name some-clickhouse-server --ulimit nofile=262144:262144 clickhouse/clickhouse-server
echo 'SELECT version()' | curl 'http://localhost:8123/' --data-binary @-
```

<Note>
  L’utilisateur par défaut de l’exemple ci-dessus n’est disponible que pour les requêtes provenant de localhost
</Note>

<div id="volumes">
  ### Volumes
</div>

En règle générale, vous pouvez monter les dossiers suivants dans votre conteneur afin d&#39;assurer la persistance des données :

* `/var/lib/clickhouse/` - dossier principal où ClickHouse stocke les données
* `/var/log/clickhouse-server/` - logs

```bash
docker run -d \
    -v "$PWD/ch_data:/var/lib/clickhouse/" \
    -v "$PWD/ch_logs:/var/log/clickhouse-server/" \
    --name some-clickhouse-server --ulimit nofile=262144:262144 clickhouse/clickhouse-server
```

Vous pouvez également monter :

* `/etc/clickhouse-server/config.d/*.xml` - fichiers contenant des ajustements de la configuration du serveur
* `/etc/clickhouse-server/users.d/*.xml` - fichiers contenant des ajustements des paramètres utilisateur
* `/docker-entrypoint-initdb.d/` - dossier contenant des scripts d&#39;initialisation de la base de données (voir ci-dessous).

<div id="linear-capabilities">
  ## Capacités Linux
</div>

Certaines fonctionnalités avancées de ClickHouse nécessitent l’activation de plusieurs [capacités Linux](https://man7.org/linux/man-pages/man7/capabilities.7.html)

Elles sont facultatives et peuvent être activées à l’aide des [arguments de ligne de commande Docker](https://docs.docker.com/engine/reference/run/#runtime-privilege-and-linux-capabilities) suivants :

```bash
docker run -d \
    --cap-add=SYS_NICE --cap-add=NET_ADMIN --cap-add=IPC_LOCK \
    --name some-clickhouse-server --ulimit nofile=262144:262144 clickhouse/clickhouse-server
```

Pour en savoir plus, consultez [&quot;Configurer les capacités CAP&#95;IPC&#95;LOCK et CAP&#95;SYS&#95;NICE dans Docker&quot;](/fr/resources/support-center/knowledge-base/troubleshooting/configure-cap-ipc-lock-and-cap-sys-nice-in-docker)

<div id="configuration">
  ## Configuration
</div>

Le conteneur expose le port 8123 pour l’[interface HTTP](/fr/concepts/features/interfaces/http) et le port 9000 pour le [client natif](/fr/concepts/features/interfaces/tcp).

La configuration de ClickHouse est définie dans un fichier &quot;config.xml&quot; ([documentation](/fr/concepts/features/configuration/server-config/configuration-files))

<div id="start-server-instance-with-custom-config">
  ### Démarrer une instance de serveur avec une configuration personnalisée
</div>

```bash
docker run -d --name some-clickhouse-server --ulimit nofile=262144:262144 -v /path/to/your/config.xml:/etc/clickhouse-server/config.xml clickhouse/clickhouse-server
```

<div id="start-server-custom-user">
  ### Démarrer le serveur avec un utilisateur personnalisé
</div>

```bash
# $PWD/data/clickhouse should exist and be owned by current user
docker run --rm --user "${UID}:${GID}" --name some-clickhouse-server --ulimit nofile=262144:262144 -v "$PWD/logs/clickhouse:/var/log/clickhouse-server" -v "$PWD/data/clickhouse:/var/lib/clickhouse" clickhouse/clickhouse-server
```

Lorsque vous utilisez l’image avec des répertoires locaux montés, vous voudrez probablement spécifier l’utilisateur afin de conserver le propriétaire correct des fichiers. Utilisez l’argument `--user` et montez `/var/lib/clickhouse` et `/var/log/clickhouse-server` dans le conteneur. Sinon, l’image signalera une erreur et ne démarrera pas.

<div id="start-server-from-root">
  ### Démarrer le serveur en tant que root
</div>

Démarrer le serveur en tant que root est utile lorsque l’espace de noms utilisateur est activé.
Pour ce faire, exécutez :

```bash
docker run --rm -e CLICKHOUSE_RUN_AS_ROOT=1 --name clickhouse-server-userns -v "$PWD/logs/clickhouse:/var/log/clickhouse-server" -v "$PWD/data/clickhouse:/var/lib/clickhouse" clickhouse/clickhouse-server
```

<div id="how-to-create-default-db-and-user">
  ### Comment créer une base de données et un utilisateur par défaut au démarrage
</div>

Il peut arriver que vous souhaitiez créer un utilisateur (l’utilisateur nommé `default` est utilisé par défaut) et une base de données au démarrage d’un conteneur. Vous pouvez le faire à l’aide des variables d’environnement `CLICKHOUSE_DB`, `CLICKHOUSE_USER`, `CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT` et `CLICKHOUSE_PASSWORD` :

```bash
docker run --rm -e CLICKHOUSE_DB=my_database -e CLICKHOUSE_USER=username -e CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1 -e CLICKHOUSE_PASSWORD=password -p 9000:9000/tcp clickhouse/clickhouse-server
```

<div id="managing-default-user">
  #### Gestion de l’utilisateur `default`
</div>

L’utilisateur `default` a l’accès réseau désactivé par défaut si ni `CLICKHOUSE_USER`, ni `CLICKHOUSE_PASSWORD`, ni `CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT` ne sont définis.

Il est possible de rendre l’utilisateur `default` accessible de manière non sécurisée en définissant la variable d’environnement `CLICKHOUSE_SKIP_USER_SETUP` sur 1 :

```bash
docker run --rm -e CLICKHOUSE_SKIP_USER_SETUP=1 -p 9000:9000/tcp clickhouse/clickhouse-server
```

<div id="how-to-extend-image">
  ## Comment étendre cette image
</div>

Pour effectuer une initialisation supplémentaire dans une image dérivée de celle-ci, ajoutez un ou plusieurs scripts `*.sql`, `*.sql.gz` ou `*.sh` dans `/docker-entrypoint-initdb.d`. Une fois `initdb` appelé par le point d’entrée, tous les fichiers `*.sql` sont exécutés, tous les scripts `*.sh` exécutables sont lancés, et tous les scripts `*.sh` non exécutables trouvés dans ce répertoire sont chargés afin d’effectuer une initialisation supplémentaire avant le démarrage du service.

<Note>
  Les scripts dans `/docker-entrypoint-initdb.d` sont exécutés dans **l’ordre alphabétique** des noms de fichier. Si vos scripts dépendent les uns des autres (par exemple, un script qui crée des vues doit s’exécuter après celui qui crée les tables référencées), assurez-vous que les noms de fichier sont ordonnés correctement.
</Note>

Vous pouvez également fournir les variables d’environnement `CLICKHOUSE_USER` &amp; `CLICKHOUSE_PASSWORD`, qui seront utilisées par clickhouse-client pendant l’initialisation.

Par exemple, pour ajouter un autre utilisateur et une autre base de données, ajoutez ce qui suit à `/docker-entrypoint-initdb.d/init-db.sh` :

```bash
#!/bin/bash
set -e

clickhouse client -n <<-EOSQL
    CREATE DATABASE docker;
    CREATE TABLE docker.docker (x Int32) ENGINE = MergeTree
    ORDER BY ();
EOSQL
```
