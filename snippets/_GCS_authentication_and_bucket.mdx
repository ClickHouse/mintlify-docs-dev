### Create a service account HMAC key and secret <a id="create-a-service-account-hmac-key-and-secret"></a>

Open **Cloud Storage > Settings > Interoperability** and either choose an existing **Access key**, or **CREATE A KEY FOR A SERVICE ACCOUNT**.  This guide covers the path for creating a new key for a new service account.

<Image size="md" img="/images/integrations/data-ingestion/s3/GCS-create-a-service-account-key.png" alt="Generating a service account HMAC key in GCS" border />

### Add a new service account <a id="add-a-new-service-account"></a>

If this is a project with no existing service account, **CREATE NEW ACCOUNT**.

<Image size="md" img="/images/integrations/data-ingestion/s3/GCS-create-service-account-0.png" alt="Adding a new service account in GCS" border />

There are three steps to creating the service account, in the first step give the account a meaningful name, ID, and description.

<Image size="md" img="/images/integrations/data-ingestion/s3/GCS-create-service-account-a.png" alt="Defining a new service account name and ID in GCS" border />

In the Interoperability settings dialog the IAM role **Storage Object Admin** role is recommended; select that role in step two.

<Image size="md" img="/images/integrations/data-ingestion/s3/GCS-create-service-account-2.png" alt="Selecting IAM role Storage Object Admin in GCS" border />

Step three is optional and not used in this guide.  You may allow users to have these privileges based on your policies.

<Image size="md" img="/images/integrations/data-ingestion/s3/GCS-create-service-account-3.png" alt="Configuring additional settings for the new service account in GCS" border />

The service account HMAC key will be displayed.  Save this information, as it will be used in the ClickHouse configuration.

<Image size="md" img="/images/integrations/data-ingestion/s3/GCS-guide-key.png" alt="Retrieving the generated HMAC key for GCS" border />
